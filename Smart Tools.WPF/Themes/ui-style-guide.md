# Smart Tools – UI style & structure guide

Standing instruction from Alan: **every view gets this treatment** – friendly, dynamic, not flat – and its backend follows the Manager + Model split. Apply it whenever a view is touched, without being asked again.

## Structure (per tool)
- `Tools/<Category>/<Tool>/<Tool>Model.cs` – plain data only (enums, INotifyPropertyChanged items, records). No WPF controls, no I/O.
- `Tools/<Category>/<Tool>/<Tool>Manager.cs` – all logic (I/O, network, audio, persistence). No WPF controls. Create it on the UI thread; raise events back on the captured `SynchronizationContext`; implement `IDisposable`.
- View code-behind – UI only: read controls → call the manager → render the result. Keep every existing `x:Name` and event handler name.
- MainWindow `Window_Closing` releases views that own resources (`CloseActiveConnection()`, `ReleaseAudio()`, ...).
- Shared model types live in their own files (e.g. `Models/BulkObservableCollection.cs` for lists that can hold 10,000+ items - one change notification per bulk add/remove). Never reference another tool's model file.
- Per-item status is an **enum** in the model (e.g. `Pending/Processing/Done/Skipped/Failed`) plus a text property; the view colours status chips from theme tokens with DataTriggers (see `StatusChipTemplate` in BackgroundRemoverView). Never put colour hex strings in models.
- Long scans/searches stream results: the manager raises an event (posted to the captured UI context) per item so rows appear live; cancelling keeps what was already found.
- Long batch runs: manager takes `IProgress<T>` + `CancellationToken`, bounded parallelism, per-item error isolation; the view shows live count pills (done / skipped / failed / ETA) and the primary button flips to Cancel (swap icon + label, never replace `Content`).
- Namespaces: `Smart_Tools.WPF.Controllers`, `Smart_Tools.WPF.Models`. Types several tools share (e.g. `RgbColor`, `ColorManager.TryHexToRgb` used by Barcode/QR) live there too - never in a tool-specific sub-namespace.
- Keep WPF drawing out of engine files: split a manager into `X.cs` (pure, unit-tested) and `X.Render.cs` (partial, WPF) so the logic compiles in a plain net8.0 test project. The project also references WinForms, so alias clashing names (`MessageBox`, `SaveFileDialog`, `Point`, `Path`, `KeyEventArgs`, ...).

## Layout
- No per-view page header: MainWindow's header card already shows the tool's icon, section and name.
- Content margin `16,8,16,16`; options sidebar 280 px, collapses to 56 px (`TuneVariant` icon toggle).
- Sidebar = `SidebarPanelStyle`; each settings group is a `SidebarGroupCardStyle` card that opens with a `SidebarGroupHeader` (gradient icon chip + CAPS label, icon passed via `Tag="{x:Static materialDesign:PackIconKind.X}"`).
- Content cards = `CardStyle`, with a `CardHeader` (icon chip + title) where a card has a heading.

## Colour and theme rules
- Only theme tokens (`{DynamicResource ...}`); no hex literals in views except on fixed-dark stages (for example the audio visualizer).
- Never set `Foreground="White"` on icons inside themed buttons (invisible in Light). White is fine only on accent/gradient fills.
- Filled accent surfaces with white text use `AccentFill`; `AccentColor` is for text, borders and indicators.
- Set colours from code with `SetResourceReference(...)`, not `TryFindResource`, so they follow theme switches.
- No `Effect` on an element that contains text or large content (it blurs the text and slows rendering). Cast shadows from an empty sibling layer instead (`ElevatedCardHost`, input glow layer).

## Shape, type and window chrome (soft-modern pass)
- Radius scale in `Controls.xaml`: `RadiusSm` 6 (chips), `RadiusMd` 8 (buttons, inputs, toggles), `RadiusLg` 12 (cards, sidebar panel). Prefer these over new literals.
- App font is `AppFont` (Segoe UI Variable Text, falling back to Segoe UI), set on `MainWindow`. Type scale: page title 20, section heading 14, body 12.5, caption 11.5.
- Control heights: button 32, primary button 36, TextBox 32, mode toggle 36. Hover on buttons is a faint wash and glow; there is no lift.
- The shell sidebar is a floating 16px-radius rail (12px gap left/bottom, so `SidebarExpandedWidth`/`SidebarCompactWidth` in `MainWindow.xaml.cs` are 252/76, not 240/64). Nav pills are 8px radius.
- DataGrid: no zebra striping, transparent muted column headers, 40px rows, rounded hover/selection wash per row. ComboBox matches TextBox (32px, 8px radius, 10px popup).
- DataGrid width: a grid never scrolls sideways (the global style sets `HorizontalScrollBarVisibility=Disabled`), so the columns have to shrink instead.
  - Fixed pixel widths only for checkboxes, icons, and short values (size, date, status). Everything that can run long is a star column with a small `MinWidth` (60 to 90). No `Auto` columns: they grow with the content and push the others out.
  - Text columns always get an `ElementStyle`. Names, paths, vendors, and inputs use `EllipsisCellTextStyle` (one line, ellipsis, full text in the tooltip). Values that must stay readable in full (hashes, summaries, regex meanings) use `WrappingCellTextStyle`. A hash has no spaces, and `TextWrapping=Wrap` still breaks it by character.
  - Set `MinRowHeight`, never `RowHeight`: a fixed height clips wrapped text.
  - Never put a trimmed `TextBlock` in a horizontal `StackPanel` inside a cell: the panel measures at infinite width, so the text never trims. Use a `Grid` with `Auto` columns for the icon and tags and a `*` column for the name.
  - Column headers trim too (shared header template), so a long header can't push the sort arrow.
- Cards use a hairline `CardBorder` plus the soft `CardElevation` shadow (blur 24, depth 4, low opacity).
- `MainWindow` uses `WindowChrome` with its own 40px title bar (`TitleBar` row, caption buttons via `TitleBarButtonStyle`). While maximized, `RootGrid.Margin` is set to `SystemParameters.WindowResizeBorderThickness` so content isn't clipped by the frame. New dialogs should keep the standard Windows chrome.

## Dialogs and message boxes
- Messages (info, warning, error, Yes/No questions) use `ThemedMessageBox.Show(...)` (`Shared/Views/ThemedMessageBox.cs`, same overloads and results as `MessageBox.Show`), never `System.Windows.MessageBox`: it is modal and follows the theme (`ContentBg`, `TextPrimary`, status icon colours). It falls back to the Windows box only before the theme is loaded.
- Custom dialogs: `ShowDialog()` with an owner, `SetResourceReference(BackgroundProperty, "ContentBg")`, standard Windows chrome; see `SavedFileDialog.cs`. Floating widgets, the Ctrl+K palette and the recorder bar stay non-modal on purpose. Windows Open/Save/Folder pickers cannot be themed.

## Shared view styles (do not redefine per view)
`Controls.xaml` ("HOISTED SHARED STYLES" block) now owns: `SidebarHint`, `SliderLabel`, `SliderValuePill`, `StatTileStyle`/`StatValueStyle`/`StatLabelStyle`, `MeterBarStyle`, `UnitSuffix`, `SwatchPickerStyle`, `PresetChipStyle` (sidebar chip) and `PlayerIconButtonStyle` (fixed-dark players). Use them straight from a view; only define a local style with the same key when a view really needs a different look (for example `DriveHealthView` keeps its own `StatTileStyle`, `MockDataGeneratorView` its card-coloured `PresetChipStyle`).
- Radii in views follow 6 / 8 / 12. Off-scale values (7, 9, 10, 11, 14) were mapped onto the scale; pills, circles (fixed size of 48 or less) and joined groups (`8,0,0,8`) are deliberate and left alone.
- Body captions are 11 and up (10.5 is no longer used). Primary buttons are 36 tall.
- Canvas / instrument / art views (PixelArt, SpritePacker, ColorWheel, Synthesizer, MidiInstruments, InstrumentTuner, KeyboardMouseTest, GameController, Monitor tests, Memorial, ContactDeveloper) keep their own shapes.
- Views fade their content in on load, so when taking screenshots wait about 1.5 s before capturing.

## Guided tour (Help button in the page header)
- The header's Help button tours **only the page that is open**; it never moves on to another page. It is enabled when the page has at least one tagged control.
- Every tool in the catalog has a tour; a new tool is not finished until it does. To add a tour to a view: add `xmlns:ctl="clr-namespace:Smart_Tools.WPF.Controllers"`, then tag the controls worth explaining: `ctl:Tour.Key="Str_Tour_<Tool>_<Part>" ctl:Tour.Order="1"`. Tag the sidebar group cards, the Input and Output card instances, the primary action, and the main result area. Three to six steps is plenty.
- Add `Str_Tour_<Tool>_<Part>_Title` and `Str_Tour_<Tool>_<Part>_Text` to both `en.xaml` and `es.xaml`. A step with neither string is skipped; controls that are hidden or collapsed (for example, inside the collapsed options sidebar) are skipped too.
- Don't put `Tour.*` on anything inside the Input/Output cards' own XAML (they have no `x:Name`); tag the card instance in the view instead.
- Logic: `Shared/Controllers/Tour.cs`; layer: `Shared/Views/TourOverlay.xaml` (the dim layer uses the `TourScrim` token).

## Motion (Themes/UiMotion.cs)
- `UiMotion.Pop(el)` when a value/badge changes (status pill, count pill, album tile).
- `UiMotion.FadeIn(el)` when content is replaced (new response, new track).
- `UiMotion.FadeVisibility(el, bool)` to show or hide overlays, empty states and messages.
- All three respect Windows' reduced-motion setting. Keep durations 150–350 ms; springy `BackEase` only on release/arrival.
- Live data can drive subtle motion (for example, the album tile pulses with bass), always smoothed and settling to rest when idle.

## Rendering and export (learned on Barcode Generator)
- WPF drawing (DrawingVisual, RenderTargetBitmap, encoders) must run on an STA thread. Background work that renders uses `ZxingImageHelpers.RunOnStaThread`, never `Task.Run`.
- Batch result rows keep a small thumbnail only; export re-renders at full size. Full images per row cost gigabytes at 10,000 rows.
- Exports stay lossless where it matters: vector SVG (real `<rect>` bars), PDF via `PdfLiteWriter.SaveBitmapAsPdf` (FlateDecode), PNG as the default. JPG is offered with a "can soften edges" hint.
- Batch exports never overwrite: `UniquePath` adds " (2)", " (3)".
- Size fields get one-click presets (chips with `Tag="WxH"`); colour pairs get Swap / Reset buttons and a contrast warning panel (below 4.5:1 or inverted).
- Clipboard calls stay in the view, not the manager.
- Live previews that can get expensive (large sizes, logos) are debounced with a ~120 ms DispatcherTimer; toggles can still render immediately.
- When a setting forces another (a QR logo forces High error correction), disable the overridden control and show an info note rather than silently changing the user's choice.

## Data visualisation and navigation (learned on Disk Space Analyzer)
- Data colours (file-type categories, chart segments) are the one exception to "no hex": they come from the manager (`ColorFor(category)`), mean the same thing in both themes, and are cached as frozen brushes. Text drawn on them picks black or white with `ColorManager.BestTextColor`.
- Treemaps use the squarified layout in the manager (`Squarify`), 2 px gaps, rounded tiles, an `AccentColor` border on hover, and labels only where they fit. Tile colour by category, never by `GetHashCode` (random per run).
- Hierarchies get a clickable breadcrumb (`CrumbButtonStyle` segments with ChevronRight separators, scrolled to the end) plus an Up button; going up re-selects the folder you came from.
- Filters that hide rows must keep the totals honest: roll hidden items into one muted "N smaller items" row instead of dropping them.
- Show what a scan missed as a warning pill (unreadable folders, online-only cloud files), never silently.
- Heavy per-view analysis (breakdowns over a big tree) runs in `Task.Run` with its own CancellationToken, is cancelled on navigation, and is awaited before the tree is mutated.
- Destructive actions run off the UI thread, confirm with a size summary, and say "permanently" when the target has no Recycle Bin.
- `MouseDoubleClick` on a DataGrid only acts when the source is inside a `DataGridRow` (not the header, scrollbar or a row button).
- Tools with options remember them between sessions (JSON in `%AppData%\Smart Tools`) and restore them on first load.
- Remember how a tool is set up, never which folders the user picked. Source and destination paths stay in memory for the session only. When a settings file from an older version still has them, strip them on load by rewriting the file. The only exception is an undo journal, which needs the paths to put files back and is deleted after the undo.

## Live measurements (learned on Disk Speed Test)
- Measure what you claim: benchmarks bypass caches (unbuffered I/O with aligned, pinned buffers) or say plainly, with a warning pill, when they couldn't.
- Throttle progress to about 10 updates a second in the manager, never one per block or item.
- Live runs show steps as pills (pending, active in the accent or info colour, done with a tick), outline the tile being measured, and draw a small live chart (Polyline plus a faint area and a dot on the newest point, a round scale from `NiceCeiling`).
- Speed tools share one look (Disk Speed Test is the reference; Internet Speed Test matches it): step pills in the run bar, tiles with a 28 px icon chip + 34 pt number + thin `MeterBarStyle` meter + a detail line, the first pass in `AccentColor` and the second in `StatusInfoFg`, a filled live chart with dashed quarter lines and a divider between passes, result pills in the card header, and history as cards with bars scaled to the fastest saved run (moved under the results on narrow windows).
- Check inputs live in the sidebar (where it will run, free space against what's needed, or why it can't run) instead of only failing on Start. The check runs off the UI thread and ignores superseded results.
- Pick a working default: when the chosen place can't be written (a drive root without admin rights), use a writable folder on the same drive and say so.
- Temporary files use a fixed prefix and are cleaned up on every path; leftovers from a killed run are removed on the next run.
- Session results worth comparing (speed runs, colour history) are saved (capped JSON in `%AppData%\Smart Tools`), with relative bars so runs compare at a glance.

## Status cards (learned on Drive Health)
- Bind item cards straight to the model and colour them with DataTriggers on status enums and `Has*`/`*Alert` flags on theme tokens. No converter classes and no hard-coded status hex colours.
- A verdict always comes with its reasons: a short findings list (icon by severity, bold title, one line on what it means and what to do).
- Only show what the source actually reported (tiles hidden when the value is null). When nothing is available, say why for that item (USB bridge, RAID, needs admin) instead of a generic "unavailable".
- Offer elevation only when it would add data. Confirm before restarting the app, and let the banner be dismissed.
- Responsive card grids: a WrapPanel with a `CardWidth` dependency property set from the scroller width (1 or 2 columns). Avoid UniformGrid, which forces equal heights.
- Refresh keeps the current cards on screen while it reloads (spinning icon plus a thin bar); the empty-state placeholder only shows when there's nothing yet.
- Windows-only code (WMI, P/Invoke) lives in its own partial files, so the pure logic compiles and is tested on its own. Buffer layouts are checked with `Marshal.SizeOf`/`OffsetOf` tests.

## Results you act on (learned on Duplicate Finder)
- Grouped results use a `ListCollectionView` grouped by a group object (not an int). The group header binds `Name.Title` etc. and the group raises `PropertyChanged` when its selection changes. Keep `VirtualizingPanel.IsVirtualizingWhenGrouping="True"`. To replace results, build a new list and a new grouped view and assign it to `ItemsSource`. Never add to the source inside `DeferRefresh()`: WPF throws "Cannot change or check the contents... while Refresh is being deferred".
- Pre-select only when it's safe: content-verified matches get "keep one, select the rest"; name-only matches are never auto-selected, and they show a warning pill.
- Before a destructive batch, warn when a group would lose every copy, default to the Recycle Bin, and say "permanently" when a drive has none. Run the batch off the UI thread, then drop handled items and groups that no longer qualify.
- Radio buttons that trigger actions use `Click`, not `Checked`: `Checked` also fires when a binding sets the value.
- Coalesce summary updates from item `PropertyChanged` with one `Dispatcher.BeginInvoke(Background)`, so bulk selection doesn't recompute thousands of times.
- Heavy scans run entirely in `Task.Run`, including listing and grouping. Parallelism follows the drive type (SSD: cores; HDD, unknown or network: 2) via `DriveHealthManager.GetMediaKindForPath`.
- Drawers slide in (TranslateTransform X 48 to 0, CubicEase) over a black scrim at 0.35 opacity. Menus built in code put an icon in the header, since the themed MenuItem has no Icon slot.
- Folder lists accept drag and drop, with an accent border while dragging over them. `OpenFolderDialog` with `Multiselect` replaces WinForms `FolderBrowserDialog`.
- Model types stay WPF-free: previews are held as `object`, and the view assigns an `ImageSource`.
- **Bulk check menu.** Every grid with per-row checkboxes that act on files (Duplicate Finder, Find Similar Files, Junk File Cleaner, Secure File Shredder, Validate Files) gets Check all, Uncheck all, Check highlighted rows, Uncheck highlighted rows, and Invert checks in its right-click menu. Add it with `BulkCheckMenu.Append(...)` (`Shared/Views/BulkCheckMenu.cs`; rules in `Shared/Controllers/CheckSelectionHelper.cs`), not a hand-built copy. Pass `eligible` to skip rows that are already deleted or shredded, `canRun` to disable it while a run is busy, and a callback that refreshes the tool's counts. "Highlighted" means the grid's selected rows (Shift/Ctrl-click), so the grid needs `SelectionMode="Extended"`.

## Media compare and big views (learned on Find Similar Files)
- One overlay per job, not per media type. Switch its content by kind (Image, or a MediaElement for video and audio) instead of copying the markup three times.
- Media sits on a fixed-dark stage (`#0E0F12`) with the player chrome (`PlayerIconButtonStyle`, `PlayerPrimaryButtonStyle`, `PlayerSliderStyle`). This is the one place hex colours are fine; the surrounding chrome uses theme tokens.
- Always release MediaElement files (Stop, then `Source = null`) when closing, when the view unloads (`Unloaded`), and before Move or Delete touches a file that's on screen.
- Formats MediaElement can't play are converted before playback (not after `MediaFailed`, which isn't reliable). Keep a cache of converted copies, delete them on close, and sweep leftovers from crashed runs on the next start.
- Only offer options that work. Hide unimplemented methods instead of listing them and throwing "not implemented".
- Pure maths (hashes, FFT, clustering) goes in its own static class with no image or ffmpeg libraries, so it compiles and is tested against a port of the old code. Decoders are injectable (a delegate), so scan orchestration is tested with fake fingerprints.
- Split views over about 800 lines into partial files by feature (`.Compare.cs`), with the main file keeping sidebar, scan and results.
- `ValueChanged`, `Checked`, `SelectionChanged` and `TextChanged` can fire during `InitializeComponent`, before controls further down the XAML exist. Every such handler starts with `if (!_viewConstructed) return;` (a null check on one control isn't enough), and the initial display is set explicitly on load.
- Sliders that drive a setting show the live value in a pill plus a one-line plain-language hint of what that value means.

## Batch jobs with settings (learned on File Converter)
- Default save folders are `<Windows library>\Smart Tools\<Tool>` - Pictures for images, Videos for video, Music for audio, Documents for everything else (for example `Pictures\Smart Tools\Convert`, `Documents\Smart Tools\PDFs`, `Music\Smart Tools\Recordings`). One `Smart Tools` folder per library, one subfolder per tool; never a flat `Smart Tools <Tool>` name. Made on the first save. Temp work folders are separate (`%TEMP%`).
- Every image format has a longest side it can store (`ConverterManager.MaxSideFor`: WebP 16383, AVIF 16384, JPG 65500, GIF 65535, ICO 256). Shrink to it before writing: a big SVG (20000 px, or sized in mm) saved as PNG but failed as WebP with "width or height exceeds limit". An SVG is one picture, so it skips the animation pre-read. Wrap Magick errors with the file and target format.
- Read choices by `Tag` (the enum name), not by combo index, so reordering the XAML can't silently change what runs. Short option sets are chip rows (`ModeToggleButtonStyle` in a `UniformGrid`, each with its own `GroupName`). Longer ones stay combos with `ComboBoxItem Tag="..."`.
- Don't offer combinations that fail. Disable the choices a setting rules out (for example, codecs a container can't hold) and say why in a muted note underneath. Remember the user's own pick, so it comes back when it's allowed again. Settings that don't apply (quality for lossless formats) are disabled with the reason, not silently ignored.
- Every setting change rebuilds the list at once from the cached file listing, without touching the disk. Only adding files, removing them or changing "Include subfolders" re-reads folders, and that runs off the UI thread and is cancellable. "Remove selected" goes into a set that survives rebuilds.
- Row status is an enum. The chip colour and icon come from `DataTrigger`s in the cell template, not a string converter, and the reason sits in the chip's tooltip. While a row runs, a 3px progress bar sits under its chip.
- External tools report live progress (ffmpeg `-progress pipe:1` plus the ffprobe duration). Write to a temp name in the destination, then move it into place under a lock. Clashes get " (2)". Stop the process on cancel or when it has been silent too long, and turn its error log into a plain sentence ("This file has no audio track.").
- Output goes where the sidebar says: a chosen folder (default under the user's Videos, Pictures or Music) or next to the originals, with "Keep folder structure" so files with the same name don't collide. Sidebar controls are disabled during a run.
- Test with the real engine where the workspace has it (ffmpeg with lavfi test sources): every allowed format × codec × bitrate combination, mono and stereo.

## Tools that move the user's files (learned on Organize Files)
- The preview is the plan. Rebuild it (debounced about 350 ms, cancelling the previous one) whenever a setting changes, and before running if a rebuild is pending. Never run a preview built with old settings. Re-read the disk only when the folder, subfolder or hidden-file options change, or after a run. Cache slow metadata (ffprobe, image headers) by path, size and date.
- Mutually exclusive checkboxes become one set of mode chips (By rules / Flatten / Keep folders). Show the result as a live example path ("🖼️ Images\2024\holiday.jpg").
- Rule lists are an `ItemsControl` bound to row models (number, criterion, can-move-up/down), not controls built in code. The combo binds `SelectedValue` to the row and uses a shared grouped `ICollectionView` with `IsSynchronizedWithCurrentItem="False"`.
- Group the preview by destination folder (group header: folder icon, name, count), so the new layout reads like a tree.
- Safety defaults: leave hidden and system files alone; skip the destination tree when it's inside the source; make every folder name safe (`/`, `?`, reserved names like CON); treat a same-named file as "already there" only when the content matches (SHA-256); otherwise save as " (2)". Choose the final name and move into it under one lock. Copy to a temp file, then rename.
- Retry a move/copy/delete a few times (100-800 ms back-off, outside any shared lock) when the file is busy: a freshly made zip is often held by antivirus or Explorer. Name the cause in the row message (in use / access denied / gone) and list failed files after the run. Clear read-only on a copy before setting its times.
- "Remove empty folders" must treat `desktop.ini` / `Thumbs.db` / `.DS_Store` as empty, and Flatten sweeps the whole source tree (not just folders a moved file came from). Flattening in place (destination == source) is legal, so never skip "under the destination" when it is the source itself.
- Undo is a journal on disk (`%AppData%\Smart Tools\*_undo.json`), so it survives a restart. Undo recreates deleted source folders before moving files back, and removes the folders the run created once they're empty.

## Renaming files (learned on Rename Files)
- A name that's taken gets " (2)" in the preview instead of being skipped as a "Collision". Taken means: a file staying put, another file in the batch, or a file on disk that isn't being renamed. Names that other batch files are leaving are free, so swaps (a↔b), chains (1→2→3) and changes of case alone (photo → Photo) are allowed.
- Run renames in dependency order: a file waits until its new name is free, and a circle is broken by parking one file under a marked temporary name (`<name>.renaming-<id>.tmp`). Settle blocked files with a work queue, never recursion (a 20,000-file chain must not overflow the stack). Cancelling never leaves a file parked.
- The undo journal records every physical move, stop-overs included, and undo plays it backwards. A change of case alone is undone too. When the old name has been taken since, the file comes back as " (2)". A cancelled undo saves the steps it didn't reach.
- Make names safe for Windows in the preview, so what runs is what was shown: replace forbidden characters, trim trailing dots and spaces (Windows drops them silently), block reserved names (CON, NUL...) and names over 255 characters, and give the reason in the status tooltip.
- A setting that's wrong as a whole (an invalid or catastrophically slow pattern, an empty new extension) shows one banner above the list, not an error on every row. Compile a pattern once per preview, with a timeout, and stop at the first timeout.
- Numbering follows natural order (2 before 10), with options for date order and restarting in each folder. Whole-word matching means "not touching a letter or digit", so `_` counts as a boundary (2024 in IMG_2024).
- Only offer an extension change as "change the name, not the file", with a warning pointing to File Converter. Lower/UPPER extension chips cover the common case.
- Rename rebuilds the plan from the settings on screen right before confirming, even when auto preview is off.
- "Clean copy suffixes" strips copy leftovers one marker per round (`_1`, `-1`, ` - Copy`, a second `(2)`). Digit limits protect real names: `_` counters are 1-3 digits (`IMG_0001` stays), `-` counters need a non-digit before them (`2024-01-15` stays), and a lone `(1)` is kept. Spaces inside the name are never changed, and a name is never emptied. A cleaned name that's taken gets " (2)" like every other rule.

## Viewing images (learned on Image Viewer, now the Photos page of Media Viewer)
- Photos stand the right way up: read the EXIF orientation (`System.Photo.Orientation`) and turn, then mirror (`OrientationTransform`, tested against the standard corrections for all 8 values). ImageMagick's `AutoOrient` covers HEIC/AVIF and the fallback path.
- Open image files through a `FileStream`, never `new Uri(path)`: a `#` or `%` in a file name broke the Uri. Read the header first (size, orientation) and decode no bigger than needed: thumbnails at their display size, and anything over 12,000 px on the long side scaled down with a note ("shown smaller to save memory").
- 100% means one image pixel per screen unit: set the Image's `Width`/`Height` to the bitmap's pixel size with `Stretch="Fill"`. `Stretch="None"` follows the file's DPI, so a 300-dpi scan showed at a third of its size.
- Fit never enlarges a small image and keeps fitting as the window or panels resize. Zoom steps are round percentages. Ctrl + wheel and double-click zoom around the mouse. Dragging to pan only works (and only shows the hand cursor) when there's something to pan.
- Load thumbnails only for rows scrolled into view (`DataGrid.LoadingRow`), a few at a time behind a `SemaphoreSlim`, with a token that Clear cancels.
- Drop the result of a superseded load before showing anything, including its error. Show a thin loading bar only when a load takes more than about 150 ms.

- Rows highlighted by the shared `PlaylistRowStyle` must expose `IsNowPlaying` (a differently named flag silently never highlights).

## Making PDFs from images (learned on Images to PDF)
- The list order is the page order, and a tick box decides what goes in. The old list had every image "selected" with no tick box on screen, so Remove Selected removed everything. Removing works on the highlighted rows (Delete key), moving on the highlighted rows as a block (↑/↓ buttons, Alt+↑/↓), and there are Sort by name (natural) and Sort by date buttons.
- Sidebar entries (one per folder or add) update their counts whenever images leave the list, and disappear when empty.

- Page setup per page: orientation can be Auto (landscape pages for wide images), and "Same as image" makes each page the picture's size (capped at 200 in). Page numbers keep 30 pt free at the bottom when the margin is smaller. A long title shrinks (28 to 14 pt) and wraps instead of running off the page.
- Quality presets also downscale (Balanced 3,500 px, Small 2,000 px). JPEG quality alone left a 48 MP photo at 48 MP. Prepare images on a few worker threads while pages go in, in list order. Transparency goes onto white, CMYK becomes sRGB, and metadata is stripped. A plain upright RGB JPEG at High quality is used as is (no second round of JPEG loss).

- Write to temporary names (`.{name}.creating-{id}-{part}.tmp`) and rename at the end. Cancel, a crash or a run where every image failed leaves no PDF behind (the old code saved a title-only PDF and called it a success). A name that's taken gets " (2)", unless the user picked it in a Save dialog and confirmed replacing it. Split parts are `Name_1.pdf`, `Name_2.pdf` …, each also made unique.
- The PDF build sits behind an interface (`IImagePdfBuilder`), so page order, splitting, naming, failures and cancelling are unit-tested with a fake builder without PdfSharp.
- PdfSharp's `GlobalFontSettings.FontResolver` can only be set once per process. Set it under a lock, only when it's null, and catch the error if another tool set it first.

## PDF tools (learned on PDF Toolkit)
- Use one list for every operation in a multi-operation tool. Switching operation keeps the files and only clears the last results (the old view emptied the list on every switch). The list order is the merge order, the tick box decides what's included, and Split and Compress work on every ticked file, not just one.
- Read page boxes ("1-3, 5, 8-", where 8- means to the end) with `ParseRanges`. It lists what it couldn't understand instead of dropping it, and the sidebar shows the result as you type. Ranges past the end of a particular PDF are reported on that PDF's row. On valid input it matches the old parser (5,000 random cases).

## Editing video (learned on Video Stitcher, formerly Video Editor)
- Probe every clip with ffprobe JSON before a run (codec, size, frame rate, rotation, sound). Cover art isn't video, and a phone's rotation flag swaps width and height. Take the frame rate from the base rate (`r_frame_rate`) when it's 120 or less, else from the average: the average drifts when the sound runs longer than the picture.
- Join clips as they are (concat demuxer, `-c copy`) only when nothing differs: same codecs, size, frame rate, pixel format, rotation and sound layout, no fades or trims, and a container that takes the codecs. ffmpeg exits with 0 on mismatched clips and writes a broken file (checked: 5 s of clips came out as 3 s). If it does fail anyway, fall back to re-encoding.
- Otherwise fit each clip into one frame (scale down, then pad with black - never stretch), constant frame rate, yuv420p, and stereo 48 kHz sound. A clip without sound gets silence when the others have sound. Then join the parts with a copy. Use MP4 for the parts, because MKV rounds timestamps to milliseconds and a 30 fps result reported 59.94. WebM parts are VP9/Opus in Matroska.
- Choose codecs per container: WebM gets VP9 + Opus, AVI gets H.264 + MP3, everything else H.264 + AAC. Try graphics-card encoders first (shared with Video Replay) and drop one for the session when it fails (no such card). The processor encoder is the last resort.
- Fades go through black at each clip's start and end, never longer than a third of the clip. Compute them from the probed length: the old code faded out at 0 s when it didn't know the length, and the whole clip came out black.
- A clip that can't be read (or has no picture) is left out with the reason on its row, and the rest is still made. Progress comes from `-progress pipe:1` (`out_time_us`) measured against the total length, so a long clip doesn't sit at 0%.
- Write to a hidden `.{name}.creating-{id}-{n}.tmp` in the output folder and to a work folder in %TEMP%, and rename at the end. Cancel kills ffmpeg and leaves nothing behind. A taken name gets " (2)" (the old code deleted the existing file), and a "replace" from the Save dialog can never overwrite one of the input clips.
- Trims are set from the player (Start / End buttons, I / O keys) and shown as a band under the scrubber. Playing through a clip's end point moves on to the next clip, but seeking past it doesn't, so the end can still be moved.
- The preview is a real render at 640×360 or smaller (`ultrafast`), with trims and fades, in %TEMP%\Smart Tools\Editor previews. It is swept before each new preview and on close.

## Cleaners that delete for good (learned on Junk File Cleaner)
- Never follow folder links (junctions, symlinks) while scanning or removing folders. Check `FileAttributes.ReparsePoint` on every entry. The old walk used `Directory.EnumerateDirectories`, which follows them, so a link inside %TEMP% led it into Documents (checked in a test).

Use name patterns where a folder mixes things (`thumbcache_*.db`, not the whole Explorer folder; `*.log`/`*.etl` in Windows\Logs, and only files over a week old). Leave files changed in the last day (installers and running programs) unless the user turns that off. A folder that appears twice (TEMP = Windows\Temp) is listed once.

- Show one row per place on the left and that place's files in a virtualised DataGrid on the right. Expanders listing every file froze on a big temp folder. Cache group totals and refresh them on a tick. The pills and the Clean button count only ticked files.

Tell apart "in use" (sharing violation 32/33), "needs administrator" (access denied where admin is needed and the app isn't elevated) and real failures, and keep the reason on the row. Remove only folders the clean emptied, never a root. Ask once, and say everything in that one question (count, size, Recycle Bin, open browsers).

## Tools that destroy data on purpose (learned on Secure File Shredder)
- Never act through a link. Skip any file or folder with `FileAttributes.ReparsePoint` (symlinks, junctions, OneDrive placeholders) when scanning *and* again right before writing, and say why. The old shredder followed a link and wiped the file it pointed to, outside the chosen folder (proved in a test).
- Refuse obviously catastrophic targets up front: a whole drive, Windows, Program Files, ProgramData, the profile folder itself.
- Tidy-up after a destructive run only touches what the run changed. Remove a folder only if it held a shredded file and is now empty, walking up to the added folder and no further. Folders that were empty before stay. The old cleanup deleted every empty folder it found, through links.
- Each file ends in one of two clear states: untouched (couldn't open it, so put its attributes back) or overwritten and deleted. Stop finishes the current file; while a big file finishes, the button becomes "Stop now", which cuts the overwrite short but still deletes the file. App closing does the same.
- Show bytes, not just files (`ShredProgress` = bytes written across all passes), with a thin per-row bar. The confirm dialog says what will happen in plain words (count, size, passes, no Recycle Bin, emptied folders) and defaults to No.
- Be honest about limits: on SSDs, USB sticks, NTFS-compressed or encrypted files, old copies can survive an overwrite. Say so in a note, and name methods for what they do ("7 random passes", not "Gutmann").
- Test destruction against real files in a temp folder: read pass contents mid-run with an external `cat` (the shredder holds the file exclusively), check symlink targets survive, and check earlier-empty folders survive.

## Reading file metadata (learned on Metadata Extractor)
- ffprobe's JSON mixes types: `sample_rate`, `bit_rate` and `duration` are strings, `width` and `channels` are numbers. Read every value through one helper that accepts both. The old `TryGetInt32` on `sample_rate` threw, so every video with sound failed. Prove a parser bug by running the old code on a real file in the tests.
- Run tools with stdout and stderr read at the same time. Reading stdout to the end first deadlocks when the tool fills the stderr pipe, and a timeout placed after that read never fires. Kill the process tree on Stop or after the time limit.
- Know the special cases: cover art is a "video" stream with `disposition.attached_pic` (it's not the video). Phone video is variable frame rate, so a sensible `r_frame_rate` (≤ 240) is preferred over the 90000 timebase. Rotation lives in `side_data_list[].rotation`, so show the upright size. Tags can live on the audio stream (Ogg/FLAC), not only the container.
- Keep heavy native libraries behind a small interface (`IImageMetadataReader` → plain values such as `MetadataRational`, `byte[]`, strings), so the wording is tested without them. EXIF needs care: NUL-padded strings, 0/0 fractions (no "NaN°"), binary MakerNotes shown as "Binary data, N bytes", and repeated tags shown with " (2)".
- Metadata comes from strangers' files. CSV export guards formulas (prefix `'` on `= + - @`, but leave plain numbers like -0.7), writes a UTF-8 BOM for Excel, and names columns "Section: Property". XML strips characters XML can't hold. All exports are written via a temp file.
- Group details by section (General, Video, Audio, Image, Camera, Location, Tags, EXIF) with a `ListCollectionView` + `PropertyGroupDescription` and a filter box. The panel follows the selected row live (subscribe to its PropertyChanged). Flag privacy: a pin on rows with GPS, a "N with GPS location" pill and an "open on map" button.
- Extract only does what's left (new, failed, stopped, or skipped but now included); when everything is read, it reads everything again.
- Sidebar queue (same look as Validate, but each tool has its own group type): one entry per added folder, labelled "with subfolders" or "this folder only" as it was added. Loose files get one entry per parent folder. Each row keeps a reference to its entry, so the entry's × removes only its rows, and rows already read elsewhere keep their results. Empty entries disappear. The subfolders checkbox affects later adds only.

## Making GIFs (learned on GIF Maker)
- One pass per GIF: `setpts` (speed) → `fps` → `scale=W:-1:flags=lanczos` (never up) → `split` → `palettegen=stats_mode=diff` → `paletteuse` with `diff_mode=rectangle`. Quality presets are colours + dither (64/bayer, 128/bayer, 256/sierra2_4a); measured sizes on a 4 s clip: 2.1 / 3.1 / 4.5 MB. Progress duration is the *output* length (selection ÷ speed).
- The gif muxer's `-loop` counts repeats after the first play: forever = 0, once = -1, N plays = N-1.
- Images mode: fit every image into the first image's shape (scaled to the max width) on the chosen fill, as numbered PNGs in a work folder, then `-framerate 1000/<ms>` → one palette. Mixed sizes and formats (PNG + JPG) can't go through the concat demuxer. Unreadable images are flagged on their row and skipped.
- WPF's Image only shows a GIF's first frame. `GifAnimator` composites frames itself: offset rectangles, see-through pixels, disposal 2/3, delays under 2 cs shown as 100 ms like browsers. It reads the file into memory, so the saved GIF isn't locked.
- Show the size before saving by encoding a short sample with the real settings (3 s from the middle of the selection, or the first 5 images) and scaling it up. Debounce it (~700 ms) and cancel it on every change.
- Trim with Start/End sliders that push each other (min 0.1 s); show the frame under the slider that moved (grab ~140 ms after it stops, a newer grab cancels the older). Step back 50 ms at the end, because the last frame of a file often can't be decoded. Phone videos: ffprobe's rotation swaps width and height; ffmpeg auto-rotates the frames.
- The Output card's "will be created" check walks up to the nearest folder that exists: a default two levels deep (Pictures\Smart Tools\GIF Maker) used to show as missing.

## Measuring network speed (learned on Internet Speed Test)
- Run each direction for a fixed time (5/10/15 s) over several connections (4). A fixed size was over in a blink on fast lines and took minutes on slow ones, and one connection can't fill a fast line (a test showed 8 vs 32 Mbps on the same link). Offer a data limit for metered lines and say in the sidebar how much a test can use.
- Ping with ICMP first and fall back to timed HTTP round trips when it's blocked. Don't count the first HTTP request (it pays for DNS and TLS). Report the median and the jitter, and say which method was used. Also ping while the download runs: a big rise means bufferbloat.
- Upload: count only bytes the server confirmed (the request finished), not bytes handed to the socket - that over-counted 18-41 Mbps on a 32 Mbps link. Grow request size while requests are quick. Measure the steady speed between completion moments and group completions within 0.1 s, skipping the first quarter (TCP ramp-up).
- Add a cache-busting query and no-cache headers to every request so a proxy can't answer from cache. Check that public test servers are still alive before shipping them (speed.hetzner.de was replaced with fsn1/hel1).
- Show live numbers on tiles with the active tile outlined in the accent colour, and a small live chart (Polylines on a Canvas, top rounded to 1/2/5 × 10ⁿ so it doesn't jump). After the run, say in plain words what the numbers mean (streaming, calls and games, uploads).
- Every tool's model shares the `Smart_Tools.WPF.Models` namespace, so give a tool's types a tool prefix when the name is generic (`NetSpeedSample`, not `SpeedSample`, which Disk Speed Test already owns). Before delivering, grep the other models for each new type name.
- History keeps numbers and the server name only (newest 50). Settings write and history write never crash a run - a failed save is skipped. Turn network exceptions into a plain reason ("couldn't connect - may be blocked on this network, try another server").

## Security tools (learned on File Encryption)
- Never change a file format in a way that strands users' files. Keep reading every old version (a copy of the old encoder lives in the tests to prove it) and write new versions with a version tag in the magic bytes and any tunable (rounds) stored in the header.
- Don't weaken crypto while restyling. Use encrypt-then-MAC and check the tag over the whole file before decrypting anything. Compare with `FixedTimeEquals`. Cap header values that cost time (rounds) so a crafted file can't hang the app.
- Make batches affordable. Run the slow password step once per batch (a shared password salt, cached in a KeyRing that is wiped afterwards), then give each file its own keys with HKDF and a per-file salt. Store a short password check so a wrong password fails at once, not after reading a 4 GB file.
- The password lives only in the PasswordBoxes and the run. Never save it; settings hold the mode and options only.
- The password UI has four meter segments coloured with theme keys (Weak = error, Fair = warning, Good = info, Strong = success) and one hint (the next thing to improve). It also shows a live "Passwords match" / "Doesn't match" line, a Caps Lock pill, and a "can't be recovered" note in encrypt mode. Ask before encrypting with a weak password.
- Decide by content, not name: read the first bytes so already-encrypted files aren't encrypted twice and plain files aren't offered for decryption. Folders leave misfits out (counted on the run bar); files added one by one show as Skipped with the reason.
- Before deleting an original, re-read the new file and verify it. When the original goes to the Recycle Bin, say that the unencrypted copy stays readable there until the bin is emptied.
- Hold input files open without write sharing between "check" and "use". Work files are hidden (`.xxxx.stf-part`) and skipped by folder walks. Progress counts bytes, not files (decrypting counts two passes).
- Output names put " (2)" before the real extension (`a (2).txt.enc`), so decrypting gives back a usable name.

## Checkers and scanners (learned on Validate Files)
- Keep three verdicts apart: **Corrupted** (the file is damaged), **Warning** (readable but worth a look: password-protected, wrong extension, silent, possible bomb) and **Couldn't check** (in use, access denied, no codec). None of the last group is "corrupted".
- A renamed file isn't a broken one. Sniff the header, and when it matches another known format say "it's really a PNG file with a .jpg name".
- Never report "checks skipped" as a problem. When a tool is missing (ffmpeg), do the checks you can, add a note, and show one warning panel in the sidebar.
- Look for the end marker, not just the start. A cut-off JPEG still decodes with a grey bottom, a cut-off gzip decompresses without error in .NET, and a moov-less MP4 is the classic interrupted recording. Test each with real truncated files.
- Read only what you need (a PDF's head and tail, not the whole file), decode big pictures in strips, and check the zip-bomb ratio before extracting.
- List the rows before scanning and fill them in live, with throttled progress. Cancel keeps finished results and marks the rest Cancelled; the next run checks only those. Leave files over the size limit visible as Skipped.
- A chosen kind filters the list; it doesn't force every file through the wrong checks. "Only problems" is a live-filtered `ListCollectionView` (`IsLiveFiltering`, `LiveFilteringProperties` = Status).
- Quarantine moves files (never deletes them), gives them " (2)" names, and appends a log of original paths so each file can be put back. Reports go to Documents\Smart Tools (never next to the .exe), and the CSV defuses `= + - @` cells.
- Every option works or isn't shown. Options that did nothing (scan depth, EXIF, embedded images and fonts, archive passwords) were wired up.

- A console is a virtualized `ListBox` of typed lines (time, a coloured source chip, text), not an ever-growing TextBox. Cap it (5,000 lines) and only follow new lines when the user is already at the bottom. Offer Copy (selected lines or all) and Save.
- Resolve a host name once, before the work starts, and report "can't find that host" plainly. Clean what people paste (URLs, host:port, [IPv6]).
- Bound all network work. Limit concurrency (a port scan runs 200 attempts at once, not 1,000), put a timeout on every connect, make everything cancellable, and throttle progress. Stopping a scan keeps what it found.
- A socket session is its own object with Received and Closed events. Marshal them with `Dispatcher.InvokeAsync` at the same priority, so the last data isn't dropped behind the close, and ignore events from a session that is no longer current. Our own disconnect isn't logged as an error.
- Decode received text with a streaming `Decoder` (a UTF-8 character can arrive split across two packets). Show control characters as symbols, and offer hex in both directions.
- On Windows, turn off SIO_UDP_CONNRESET on UDP sockets; otherwise one "port unreachable" reply kills every later receive.
- Ask third-party services only on first load or on request, never on every visit, and let the user switch it off (public IP lookup).

## Players and playlists (learned on Video Replay, now the Videos page of Media Viewer)
- Track the current item by object, never by row number. A `PlayOrder<T>` holds the items: removing a row above the playing one must not move the highlight, change what Next plays, or delete the wrong file. Adding clips in shuffle inserts them ahead of the current clip without reshuffling what's already planned.
- "Plays every clip once" means stop at the end. Repeating the playlist is a separate, visible option. Previous restarts the clip after 3 s, like every player. In Loop, Next and Previous still move.
- Keep icons in buttons and switch `PackIcon.Kind`. Never replace Content with "▶" or emoji text. Mute uses `IsMuted` and keeps the volume level.
- The player chrome sits on the fixed-dark stage (`PlayerIconButtonStyle`, `PlayerPrimaryButtonStyle`, `PlayerSliderStyle`, and a pill button for speed). The now-playing line under it shows "Up next" and "3 of 12".
- Re-apply `SpeedRatio` on `MediaOpened` (MediaElement forgets it). Pause on `Unloaded` so audio doesn't carry on on other pages, and release `Source` before deleting a file.
- Formats Windows can't play get a preview copy up front (with % progress). Any other file that fails gets one retry through a preview copy. Copies live in %TEMP%\Smart Tools\<tool> previews, named by path + size + date, and are deleted on close and swept on the next start.
- Failures go in a dismissible banner on the stage and a red row with the reason; a dialog per failure stalls the playlist. Skip on, and stop when every clip has failed in a row.
- Probe durations in the background (ffprobe, 3 at a time) so the playlist shows lengths and a total ("12 clips · at least 1:23:45"). Sort folder contents naturally (Ep 2 before Ep 10).
- Playback engines sit behind one `IReplayBackend`. VLC runs from `Engines\VLC` (libvlc 3.x through P/Invoke, no NuGet) and plays WebM, MKV and FLV directly. MediaElement is the fallback when that folder is missing; its preview copies try the graphics-card encoders first (nvenc → qsv → amf → mf → libx264) and remember which one worked. An engine pill says which engine is in use.
- libvlc rules: load `libvlccore.dll` then `libvlc.dll` by full path, and check the DLL is the same bitness as the app first. Poll `get_state` on the UI timer instead of event callbacks (calling libvlc from its own callbacks deadlocks). Treat "Playing for 1 s" as opened, because browser-recorded WebM often has no length. Apply volume, rate and mute after opening. After Ended, call stop before play.
- VLC draws into its own HWND (an `HwndHost` with CS_DBLCLKS), so nothing WPF can sit on top of it: give banners their own row. Pass double-click and right-click back from the HWND. Stop VLC in `DestroyWindowCore` (when you leave the page) and resume at the same spot on return.
- Native engines (`Engines\<Name>`) must be copied to the build output: the app looks in `AppDomain.CurrentDomain.BaseDirectory`, i.e. `bin\...\Engines`, not the project folder. Every engine folder needs a `<None Update="Engines\<Name>\**\*" CopyToOutputDirectory="PreserveNewest" />` line in the .csproj.
- When an engine can't be used, say exactly why: the full folder path checked, each missing file or folder, the usual copy mistakes (files one folder too deep, `plugins\plugins`, an empty plugins folder, files in the project but not in bin), bitness, and the version. Show a banner when the engine was clearly meant to be there. Log each start attempt to `%AppData%\Smart Tools\<engine>.log`. The loader never throws.
- libvlc threading: never call `libvlc_media_player_stop` (or anything else that can wait) on the UI thread. VLC's video thread sends messages to the window it draws in, so a stop there locks up the UI thread, and closing the app mid-clip left the process running. Run every VLC command on one command thread per player. While a command runs, the getters return the last known values, because `get_time` and `get_length` wait during a stop. Before the video window is destroyed, wait for the stop with a managed wait, which keeps messages flowing. At exit: close the player and release the instance, each with a timeout, and end the process if VLC is stuck.
- Any view that plays video or audio uses the same `IReplayBackend` pair: VLC when `Engines\VLC` loads, else MediaElement with preview copies. One VLC instance serves the whole app (`VlcPlayer.EnsureLoaded` is shared), with one `VlcBackend` per surface (Find Similar Files uses two, left and right). Each view waits for VLC to finish starting before choosing a player, gives VLC's window a spot no overlay covers (start it below badges and buttons), waits for VLC to let go of a file before Move or Delete, and in `CancelActiveRun` closes its players, calls `VlcPlayer.Shutdown`, then `VlcShutdown.Finish`.
- P/Invoke strings: `[MarshalAs(UnmanagedType.LPUTF8Str)] string` is fine for a single string, but a `string[]` can't be marshalled as UTF-8 (MarshalDirectiveException at the first call). Build the array by hand: `Marshal.StringToCoTaskMemUTF8` for each item into an `IntPtr[]`, pass that, and free each item in `finally`. Test native signatures against a small fake C library, because marshalling errors only appear when the call runs.
- An engine that starts slowly in the background (VLC's first plugin scan) must be awaited before choosing a fallback path. Otherwise the first clip takes the slow path (a preview copy) for nothing. Show a "Starting…" state while waiting.
- Keyboard: Space, ←/→ (Shift ×3), N/P, M, T/Esc for theater. Skip these while a TextBox has focus, Space on buttons, and arrows in grid cells. Theater (double-click the video) hides both side panels.

## Patterns, live text and big inputs (learned on Regex Tester)
- Anything a user types that runs user-supplied logic (a regex, a filter, a formula) gets a time limit, and the timeout is caught and explained ("too slow - it likely backtracks a lot"), keeping what was found. Catching only `ArgumentException` around a regex is a crash waiting to happen: `RegexMatchTimeoutException` isn't one.
- Live matching: debounce ~200 ms, run off the UI thread, cancel the previous run on each key press with a plain (not linked) `CancellationTokenSource`, and drop superseded results. Show "Working…" only after 150 ms so quick runs don't flicker.
- Cap what the UI builds, not what's counted: count every match, but list at most 10,000 rows and draw 2,000 highlights, and say so in the status line. Show at most ~300,000 characters in a `RichTextBox` copy.
- A highlighted copy must be the real text. Empty matches are a thin caret (`InlineUIContainer` with a 2 px accent bar), never an inserted space. Alternate two tones (`AccentColorSubtle`, `StatusWarningBg`) so neighbouring matches are told apart.
- Positions are given as line:column (1-based) as well as offsets, and clicking a result row selects it in the source text box.
- Errors point at the spot: a banner under the input with the plain reason and, for short one-line input, the input with a `^` under the error position (`RegexParseException.Offset`).
- Reading "text" files: check the BOM first (UTF-8/16/32), then treat NUL bytes as binary, then try UTF-8 with a Latin-1 fallback. The other order skips every UTF-16 file (PowerShell output, .reg files).
- A cheat sheet is clickable: each token chip inserts itself at the caret. Explanations of what the user typed (the pattern breakdown) are built by the manager, list nested parts indented under their group, carry the token's offset so a row can select it, and never throw on half-typed input. Fuzz them: 20,000 random inputs, no exceptions, and a "problem" row only where the real parser also fails.
- Folder searches take a file filter (`*.log;*.txt`, matched with `FileSystemName.MatchesSimpleExpression`), skip links, binary and over-size files, and list the skipped files with reasons in a warning pill's tooltip. A file that times out is noted and the search moves on.
- Drop target that changes mode: a dropped file opens in File mode, a dropped folder in Folder mode. Use `PreviewDragOver`/`PreviewDrop` on the root, because a TextBox swallows file drags, and handle only `FileDrop` so dragging text into a box still works.
- Settings remember the pattern and flags, never the test text (it may be private) or the file and folder.

## Searching many files (learned on File Search)
- Find every match, not the first: loop `Match`/`NextMatch` for every pattern on every line. Two patterns finding the same text are one hit that names both. Skip empty matches.
- Several patterns at once are a ticked list (a CheckBox per pattern, styled as a card with a check icon), not a dropdown that holds one. Saved patterns come from Settings and follow edits live; typed ones can be added with Enter and removed with ×. Show "3 patterns ticked" and disable patterns that don't compile, with the reason in the tooltip.
- "List each value once" works across all files: show the first place found and count the repeats ("×5 · 3 files", other files in the tooltip). In this mode read each file to the end; "one row per file" then means the file's first value that isn't listed yet. Stopping at the first match loses values.
- Parallel work, stable output: read files in parallel, but merge their rows strictly in file order (a finished-files dictionary plus a "next index" cursor), so "first found" never depends on thread timing and rows stream in a predictable order.
- Stream rows to the UI in batches about 10 times a second through `IProgress` (new rows plus count updates, applied on the UI thread with `BulkObservableCollection.AddRange`). Cancel returns what was found.
- List files without following links, once each, even when one added folder is inside another (a `HashSet` of full paths).
- Open files with `FileShare.ReadWrite | FileShare.Delete` so logs another program is writing can still be read.
- Don't offer options that can't work: line-by-line matching makes Multiline/Singleline meaningless, so they're removed rather than left as no-ops.
- Big result lists get a filter box (`ICollectionView.Filter`, debounced 200 ms), a "Copy values" button (each value once, one per line), a context menu (copy match, copy path, open, show in folder) and double-click → show in folder.
- Re-subscribe to shared stores (`AppSettingsStore`) in `Loaded`, not only in the constructor: MainWindow reuses views, so a view that unsubscribes in `Unloaded` must subscribe again when it comes back.

- With several patterns ticked, every per-file limit counts **per pattern**: "At most one row per file" gives each file its first match of each pattern (first email AND first phone) and stops reading only when all patterns were found. A limit shared by all patterns hides every pattern but the first.
## Making files on purpose (learned on File Generator)
- Write under a hidden temporary name (`.name.guid.part`) and rename when complete; delete it on cancel or failure. A half-written file must never look like a result.
- Check the plan live in the sidebar before anything is written: first … last name (with padded numbers so names sort), total size against free space, bad names/extensions (Windows reserved names, `: * ? " < > |`, trailing dot or space), and whether the folder will be created.
- "Exact size" means exact AND valid: pad inside the format's own rules - JSON/XML whitespace before the closing bracket, the last CSV value, PDF comment lines before the objects (offsets computed after), a private ancillary PNG chunk (`fiLl`), JPEG COM segments, a stored DOCX zip entry measured first, an MP4 `free` box. Only a target below the format's minimum is bigger, and the row says "smallest possible".
- Prefer small hand-written writers over libraries for simple formats (PDF, PNG, baseline JPEG, DOCX): they're testable in the plain test project and verified with real tools (qpdf, Pillow, ffprobe, zipfile).
- Escape with the platform: `JsonSerializer.Serialize(string)` for JSON strings, `SecurityElement.Escape` plus dropping XML-invalid control characters for XML. Hand-rolled escapes miss tabs and quotes.
- Fill patterns carry their offset across buffers; text output that ends mid multi-byte character gets the broken bytes replaced with spaces.
- Many options in a sidebar: chips for every small choice (formats as a 4-column tall-chip grid), InputBar + BareTextBox + BareComboBox for number+unit, one-click preset chips (`PresetChipStyle`) for common sizes and counts, and hints that change with the choice (what the format contains, where metadata goes, why the fill doesn't apply).
- Map list positions to enums by `Tag` name, never by index arithmetic in two places (the old export picked CSV for JSON because the list and the code disagreed).

## Finding big files (learned on Large File Finder)
- Keep only the N biggest with a min-heap (`PriorityQueue`, smallest on top) while scanning; never collect every match and sort at the end. Count every match (and its bytes) separately so the summary can say "50 biggest of 1,240".
- Show the biggest-so-far while it scans: a snapshot of the top 200 about twice a second, plus counters (files, folders, large, current folder) about seven times a second. The list fills in live; the final result replaces it.
- Stop keeps what was found ("Stopped. …" in the summary) - cancel returns a partial result, it never throws away the work.
- Never follow folder links (skip `ReparsePoint` folders) - the old scan looped through a junction and listed one file 41 times. Skip online-only cloud files (`Offline` and `RecallOnDataAccess` attributes): they aren't on this disk and reading them would download them. Downloaded OneDrive files stay in.
- "Ignore system files" skips System-marked items plus `$Recycle.Bin`, `System Volume Information`, `Recovery` and friends by name. "Show hidden" is off by default but the hint says AppData often holds big caches.
- Drives are read off the UI thread (a sleeping network drive can take seconds) and shown as cards with a used-space bar, system drive first, with a "Refresh the drive list" chip for a USB stick plugged in later.
- Say where a delete goes before asking: "Send … to the Recycle Bin?" only for local fixed drives; elsewhere "Delete … permanently? … can't be undone", and a mixed selection says how many of each. Default button is No. One summary box for failures, never one box per file.
- Move: refuse "already in that folder" up front (the old code renamed the file to "video (1).mp4" in place); check free space for files going to another drive; same drive is a rename; another drive is a copy to a temporary `.part` name (date kept), rename, then delete the original. Stop removes the half copy and leaves the original. If the original can't be deleted afterwards, say the file is now in both places. Name collisions check folders as well as files.
- A size column with a thin bar against the biggest file, and a stacked bar by kind (video, disk image, archive…) with chips that filter the list - "what is the space" at a glance. Kind colours are data colours (frozen brushes), not theme tokens.
- Size input = number + unit (InputBar + BareTextBox + BareComboBox) plus preset chips; the result limit is chips (25 / 50 / 100 / All), not a combo.

## Secrets on screen (learned on Password Generator)
- Randomness only from `RandomNumberGenerator` (`GetInt32`, no modulo bias), never `System.Random`.
- Show the strength of the *settings* live, before anything is generated: a pill (Very weak … Very strong) coloured with the status tokens (error / warning / success), a meter (128 bits = full), the bits as a big number, what it's made of ("88 characters × 16 · one of each type", "7,776 words × 6 + 2 digits") and a plain "cracked in about 3 years at 100 billion guesses a second" with a tooltip saying what that speed means.
- The bits must be exact for what the generator really does: use the clamped length, and for "one of each type" count the qualifying strings (inclusion-exclusion with `BigInteger`) and pick uniformly among them (draw again until it qualifies). Never report entropy for a length the generator doesn't produce.
- Passphrases use a big, well-known list (EFF long list, 7,776 words, about 12.9 bits a word, no word is the start of another) in its own `*.Words.cs` file with the source and licence in a comment. Defaults should grade at least "Strong".
- Masked by default (dots), an eye per row and a "show all" toggle (remembered - it's a preference, not a secret). Colour digits and symbols in the plain text so look-alikes are easy to read.
- Copying a secret: mark it so Windows keeps it out of clipboard history and cloud sync (`CanIncludeInClipboardHistory` = 0, `CanUploadToCloudClipboard` = 0, `ExcludeClipboardContentFromMonitorProcessing`), clear it after 30 s and on close - but only if the clipboard still holds what we put there. Say so in the status line; turn the copy icon into a tick for a moment.
- A failed copy (clipboard busy) is reported, never swallowed silently.
- Exporting secrets: plain text (one per line, exact) by default, CSV optional with invariant numbers and the formula guard; the dialog title and the status line say the file isn't encrypted. Settings never contain a secret.
- Every action that can fail on bad options is checked up front (`Validate`) and every handler catches - a row button must never crash the app.

## App shell and navigation (learned on the MainWindow rework)
- One list of tools: `Shared/Controllers/ToolCatalogManager.cs` holds every section (id, title, icon, data colour, blurb, search words) and tool (id, short name, full title, icon, section, one-line description, keywords). The sidebar, the Home page, the page header and search are all built from it. Moving a tool to another section = changing its `CategoryId`; adding a tool = one catalog line + one `Add<TView>("id", v => v.CancelActiveRun())` line in MainWindow.
- Sections group by what the person is doing, not by file type: Music (tuner, synthesizer) apart from Audio (play, record, transform); colour tools with Images; Password Generator with Security.
- Home page = section cards (coloured badge, title, blurb, count) with tool rows (tinted icon, name, description), laid out in as many columns as fit, each card in the shortest column. Search on top (Ctrl+K from anywhere, Enter opens the first match, Esc clears, ↓ moves into the results) matches the start of names and words first, then section, keywords and description, ignoring case and accents. Recent tools as chips.
- Sidebar stays slim: Home on top, Recent (last 4), collapsible section headers (chevron, colour dot, name, count; open/closed remembered), Settings pinned at the bottom. Tool icons take their section's colour. Opening a tool opens its section so the highlight is visible. Icon-only below 700 px.
- Pages are created the first time they're opened and kept (so they remember their state); a page that fails to build shows a message instead of stopping the app.
- Navigate on `Click`, never on RadioButton `Checked` (it doesn't fire for an already-selected item); pages outside the sidebar (Contact, Memorial) clear the highlight.
- On close, clean up only the pages that were opened, each in its own try/catch (one failing clean-up must not skip the rest); fall back to `IDisposable`.
- Shell settings (`shell.json`) store tool ids only - Recent and open sections; unknown ids are dropped on load.
- The sidebar does not follow the open tool (removed): sections only open or close when the user clicks them. A **Back** button in the page header (`BtnBack`, `MainWindow._history`, up to 30 pages) returns to the previous page. Recent keeps its order when a tool is opened from the Recent list or with Back (`Open(id, keepRecentOrder)`); a tool opened from anywhere else moves to the top.

## The person's own content (learned on Notes)
- Content the person typed can't be regenerated, so loading must never lead to it being overwritten: a damaged file is moved aside (`notes.damaged-<time>.json`, byte for byte) and the last good copy (`.bak`) is loaded; a file that can't be read at all (locked, or the name taken by a folder) pauses saving for the session. Tell the person in a warning bar with "Open folder".
- Save to a temporary file and swap it in with `File.Replace(temp, file, backup)` - one step, and the previous version becomes the `.bak`. Never `Copy` over the real file.
- Saving returns why it failed and the page shows it (icon + text in the status line: Saving… / Saved automatically / Couldn't save: …). Never "saved automatically" over a silent catch.
- Save half a second after typing stops, immediately on delete, when leaving the page (`Unloaded`) and on app close (register `CancelActiveRun` in the shell).
- Store only real fields (a record type for the file) - the old file also stored display text like Snippet and "Edited …". Keep the old field names so old files load unchanged.
- Delete without an "are you sure?" box but with an Undo bar for 8 seconds (Ctrl+Z when not typing).
- "New" reuses a blank note instead of piling up empty ones; blank notes are dropped when leaving.
- Reorder with `ObservableCollection.Move`, never Clear-and-refill (that deselects and resets the editor).
- Sticky-note colours stay pastel with dark text in both themes; the editor gets a faint wash plus a solid strip of the colour. Relative times ("5 min ago") refresh every minute. Word/character count in the footer. Search over title and text, accents ignored.

## The Input card (standard for every tool that takes files or folders in)
- One shared control, `Shared/Views/Extentions/InputFolderCard.xaml(.cs)` (logic in `Shared/Controllers/InputFolderManager.cs`, data in `Shared/Models/InputFolderModel.cs`). It replaces the hand-copied Files card, the folders card and the single "source folder" panel; don't build those by hand any more. The Files card section below describes the look/behaviour the Input card keeps.
- `Mode`: `Files` (queue of files and folders: Add files · Add folder · Clear), `Folders` (folders only), `SingleFolder` (one source folder: chip, name, path and a status line - green "Folder found", red "This folder isn't there any more" / "can't be read" - with Choose folder… · Open · Reset). Header defaults to "Files"; set `Header`/`HeaderIcon` otherwise.
- The card only collects paths and raises events; the view keeps its own queue model and manager: `PathsAdded` (only paths that exist), `ClearRequested`, `IncludeSubfoldersChanged` (user clicks only), `FolderChanged` (SingleFolder). The list's item look is the view's own `ItemTemplate` (its remove button's Click handler stays in the view); feed the list with `ItemsSource` and call `SetEmpty(bool)` when it changes. Page-wide drop handlers call `SetDropHighlight(bool)` and `PopDropArea()`.
- `IncludeSubfolders` (two-way) and `ShowSubfolders` control the checkbox; `IsLocked` while a run is in progress; `FolderPath` is session-only (never saved - shell/tool settings never store folder paths).
- Same rules as the Output card: no `x:Name` in the card's XAML (parts use `x:Uid`), and no named elements in its `Options` slot (MC3093) - put extra options in a separate sidebar card instead (see Organize Files: Source card, then a Destination card).
- Learned on Validate: removed rows are remembered by path so a rescan doesn't bring them back, but adding the folder (or file) again must forget them (`Unhide`) - otherwise re-adding a folder after removing its files showed an empty list. Quarantine/Move actions filter by status in the manager as well as the view, so valid files can never be moved by a stray grid selection.

## The Files card (standard for tools that take a list of files)
Used by Validate Data, Convert Files, Images to PDF, Video Stitcher, Audio Replay, Background Remover, Image Editor, PDF Toolkit and Voice Changer; build any tool that works on a list of files and folders the same way. Header "Files" (an audio tool may use FolderMusicOutline as the icon). A tool whose list is also a playlist keeps its own "Clear all" under the list as `BtnClearAll`; `BtnClearQueue` is always the card's Clear. No Files/Folder switch - both Add buttons are always visible. Dropped folders follow Include subfolders too.
- First card in the sidebar, header "Files" (icon FileMultipleOutline). - The main area shows the per-file detail (the list/grid with status); the Files card only says what was added. Clear on the card and Clear all above the list do the same thing. The bar above the list uses the standard 32x32 icon buttons (`ListToolButtonStyle` / `ListToolDangerButtonStyle` / `ListToolWarningButtonStyle` for careful-but-not-destructive actions); the Files card keeps its own 34x34 icon buttons.

Every removal path (row ×, Remove selected, Delete key, the card's ×) goes through `RemoveFromList` so the card's counts never go stale. The duplicate check runs on the UI thread after any await, never before it.
- Don't paste the card from another tool as-is: its `models:` type, its xmlns, and its handler names (`BtnAddImages_Click`, `BtnRemoveQueueGroup_Click`, `Option_Changed`) belong to that tool, and the view stops compiling. Use the standard names above and the tool's own group type (`BackgroundRemoverGroup`, `ImageEditGroup`, `PdfToolkitGroup`...).

Copying the Duplicate Finder's card brought `models:FolderListEntry`, `Str_Dup_*` keys and a renamed empty hint, and dropped Include subfolders - the view stopped compiling.
- Add files filters what the dialog returns ("All files" lets anything through); the old Background Remover queued .txt files that then failed at run time.

## The Output card (standard for every tool that saves results to a folder)
- One shared control, `Shared/Views/Extentions/OutputFolderCard.xaml(.cs)` (logic in `Shared/Controllers/OutputFolderManager.cs`, data in `Shared/Models/OutputFolderModel.cs`). Never hand-build an output picker again: a TextBox + Browse row is the flat style this replaces.
- Looks like the Files card: header "Output" (FolderArrowRightOutline), a rounded drop panel (SidebarInputBg, rounded 10) showing a folder chip, the folder's name (+ a "default" tag), the full path and a status line (green "29 GB free", blue "Made on the first save", amber "Only 600 MB free", red "isn't there any more" / "Windows won't let the app save here"). Under it: **Choose folder…** (PrimaryButtonStyle) · Open in Explorer · Reset to default, then the optional **Save next to each source file** and an example line ("e.g. D:\Exports\photo-converted.png").
- Click the panel or drop a folder on it (a dropped file means its folder); the drop is handled so a page overlay doesn't open.
- Properties: `ToolName` (default folder Documents\Smart Tools\<ToolName>), `FolderPath`, `SameAsSource`, `AllowSameAsSource`, `UseDefaultFolder`, `ExampleFileName`, `IsLocked` (set while running). Read `Status.CanSave` before starting, call `EnsureFolder()` to create it, `ResultPathFor(source, name)` for each result (never overwrites), and `Refresh()` after a run. Event: `FolderChanged`.
- Never put `x:Name` on anything inside `<controls:OutputFolderCard.Options>` (MC3093, even with the card's own parts unnamed). Build the option controls in the view's code-behind and set `OutputCard.Options = panel` (File Converter's `BuildOutputOptions`), or leave them unnamed and wire them with events.
- A shared UserControl that takes content from the page (`Options`) must not use `x:Name` in its own XAML: WPF then refuses names in the page's content (MC3093 "already had a name registered when it was defined in another scope"). The card's parts use `x:Uid` and are found once in the constructor (`CollectParts` over the logical tree).
- **File mode** (tools that save one file, e.g. Images to PDF): `ShowFileName="True"`, `FileExtension=".pdf"`, `DefaultFileName`, `AllowAskEachTime="True"`. The card adds a File name field (InputBar, FileDocumentEditOutline icon, the extension as a pill), "Ask where to save each time", and a "Saves as D:\…\Trip (2).pdf" line with the exact file. ## Playing instruments (learned on MIDI Instruments)
- Sound goes through Windows' own MIDI (winmm.dll, P/Invoke in `Engines/Midi`) - no NuGet, nothing to copy into the build folder. The manager talks to an `IMidiOut` interface, so all playing logic is unit-tested with a fake synth.
- Notes come from several places at once (mouse, computer keys, a MIDI keyboard on its own thread, playback): one lock in the manager, events raised after the lock is released, the view marshals with `Dispatcher.BeginInvoke`. The winmm input callback only queues and wakes a worker - almost no other API may be used inside it.

- A piano is black and white in both themes: the keys use local fixed brushes (`PianoWhiteKey`, `PianoBlackKey`...), the pressed key uses the theme accent and dips 2 px. Black keys are hit-tested before white ones.
- Keyboard shortcuts on a page that plays from the keyboard: skip them while a TextBox has focus, and handle Space in PreviewKeyDown so it doesn't also press the focused button. Arrow keys belong to sliders and lists when they have focus.
- Settings save the device by name (Windows renumbers devices), never a folder; the last save folder is session-only.

## Recording, speaking and changing voices (learned on Audio Recorder, Text to Speech, Voice Changer)
- These tools use NAudio 3.x and System.Speech from NuGet (the app is on .NET 10; NAudio 3 needs .NET 9+). Voice effects (pitch, robot, echo) are plain C# in `VoiceChangerDsp.cs` - one chain serves files and the live mic, tested by measuring the output frequency and echo timing. The device code sits in `<Tool>Manager.cs`; everything that doesn't need them (names, meters, SSML, file lists, settings) sits in `<Tool>Manager.Files.cs` / `.Text.cs` and is unit-tested.
- Work in progress lives in the tool's own temp folder (`%TEMP%\Smart Tools Recorder`, `…\Smart Tools Voice Changer`). Saving moves the file out (the old auto-save copied it and left the temp file behind). The tool only ever deletes inside its own temp folder, and cleans leftovers older than a day when it starts.
- Every saved name is unique: "name (2).wav", never an overwrite. A name typed in "File name" is a name, not a path: settings strip any folder from it.
- Save to card (folder + File name + Save without asking): the folder is session-only; the example line under the name shows exactly what will be written.
- Leaving the page stops sound you could no longer stop (speech, live voice, playback). A recording carries on. Closing the app finishes a recording and saves it, and cancels a WAV save without leaving half a file (write to `.part`, move when done).

- Other apps can only take our sound as a microphone through a virtual audio cable (Windows has no other way without a signed driver). Live voice has a "Send to" picker (default output or a cable), "Hear yourself too" (a second output fed from the same chain), a hint naming the exact microphone to choose in the other app, and a link to get a cable when none is installed. A cable is never picked automatically, and cable-in plus cable-out is refused as a loop.
- Speech highlight: SAPI reports positions in the SSML, so keep a text-to-SSML map and convert back; the text box is read-only while it speaks; `IsInactiveSelectionHighlightEnabled` keeps the highlight visible.

## Listening live (learned on Instrument Tuner)
- Analyse audio on a hop, not per sample: a 4096-sample window every 2048 samples (about 20 readings a second). The old tuner re-ran pitch detection after every sample once the window was full (40,000+ runs a second).
- Pitch detection covers the whole instrument range (30–1500 Hz, so a bass's low E and a 5-string's low B are found) and falls back to the deepest dip when no dip clears the threshold. Test it with synthetic plucked tones (fundamental + harmonics + noise) and check the error in cents.
- Smooth the needle, but reset it when the note changes; "In tune" needs 3 readings within 5 cents to turn on and more than 8 cents to turn off (hysteresis), so it doesn't flicker.
- Leaving the page releases the microphone at once and the page shows that it stopped.

## Following files live (learned on Log Viewer)
- Poll (300 ms) with `FileShare.ReadWrite | FileShare.Delete` instead of FileSystemWatcher. Each run keeps its own position and decoder; a stopped run raises nothing more (compare a run id).
- Hold text after the last line break until its line break arrives (or the file has been quiet for ~1.5 s); a line written in two flushes is one line. Decode with a persistent `Decoder` so a UTF-8 or UTF-16 character split between two reads isn't garbled. Detect the BOM once.
- A file that gets shorter was rotated or cleared: read again from the top and say so in the view. A missing file is waited for, not an error. A sharing violation waits for the next poll.
- Viewer notices (paused, file missing, saved…) are typed system lines in the console, never a dialog per event, and they're never exported or highlighted by rules.
- A console is a virtualized ListBox with its own template: the kit's ListBox template doesn't pass `CanContentScroll` on, which silently turns virtualization off.
- Auto-follow: only a scroll the user made (no extent/viewport change) can pause following; when the content changes and following isn't paused, scroll to the bottom with `ScrollToBottom` (not `ScrollToEnd`, which also moves sideways). Show a "12 new lines - back to the newest" button while paused.
- Several open files: a TabControl as a header strip only, with one console bound to the selected tab, so the code-behind has named controls. Remember a paused tab's first visible line and restore it on return.
- In a DataTemplate, values a trigger must override go in Style setters, not attributes (an attribute or binding set on the element beats a template trigger).
- Highlight colours chosen by the user get dark or light text by WCAG luminance (light text on yellow was unreadable). Rules apply live to every tab (debounced) and save themselves.
- Tabs keep following while you're on another page; `CancelActiveRun` stops them all. Opening a file already open selects its tab.

## NAudio 3 (learned on the .NET 10 / NAudio 3.1 upgrade)
- Providers implement `int Read(Span<float> buffer)` (`ISampleProvider`) or `int Read(Span<byte> buffer)` (`IWaveProvider`); there is no offset/count any more. Pass slices: `_source.Read(buffer.Slice(start, length))`, `_source.Read(_array.AsSpan(offset, count))`. Never write outside the span you were given.
- `AudioFileReader` is also a `Stream`, so `reader.Read(floatArray, 0, n)` now hits `Stream.Read(byte[]...)` and fails. Read samples through the interface: `ISampleProvider samples = reader; samples.Read(chunk)`.
- `WaveOut(Event).DesiredLatency` is gone: set `BufferMilliseconds`, which is per buffer (two buffers by default, so the old 100 ms total is about 50).
- `BufferedWaveProvider.BufferDuration` is read-only: pass the length to the constructor, `new BufferedWaveProvider(format, TimeSpan.FromSeconds(2)) { DiscardOnBufferOverflow = true }`.
- Floats to bytes without copying: `MemoryMarshal.AsBytes(span)` (for `AddSamples`, or `writer.Write(...)` on a float WAV writer).
- `WaveOutEvent`/`WaveInEvent` still work but are the old names of `WaveOut`/`WaveIn` (expect obsolete warnings).
- Keep the DSP in plain C# with a `Span<float>` entry point (`VoiceChangerChain.Process(Span<float>)`) so providers stay one-liners and the maths stays unit-tested. Type-check NAudio code against stand-ins of the version the app uses, and first make sure the stand-ins reproduce the user's real error list.

## Live hardware readings (learned on System Monitor)
- **System Monitor = Task Manager's Performance tab**: usage, speeds and facts come from Windows itself (PDH, Win32, WMI, DXGI) - no driver, no admin rights. Its CPU / graphics / drive **temperatures** are the one exception: they come from the same sensor library as Hardware Sensors, through the shared `SharedSensorHost` (one `Computer`, one gate so the two tools never read it at the same time), read at most every 2 s. Without administrator rights those temperatures are missing; the section says "Needs administrator" and the shared `ElevationBannerCard` explains. Fans, voltages, power and the full sensor list live in the separate **Hardware Sensors** tool.
- **Hardware Sensors = LibreHardwareMonitorLib** (NuGet, MPL-2.0): opened, read and closed only on the reading loop's thread; any exception means "no sensors" with the reason. Part list on the left (CPU, graphics, motherboard, drives...), headline tiles (temperature, load, clock, power, fan) with a one-minute graph, then every sensor grouped by kind with low/high. Pick the number people mean (Package / Tctl-Tdie, not the hottest core; core clocks averaged without the bus clock; fastest turning fan). Levels differ by part (SSD warm from 55 °C, CPU/GPU from 80 °C). When the CPU shows no temperature, say why in plain words - LibreHardwareMonitor reads CPU/motherboard through its PawnIO driver and only as administrator - without download prompts. Never share model types with System Monitor.
- Sources: PDH via P/Invoke (`\Processor Information(*)\% Processor Utility` = Task Manager's CPU %, `\Processor Information(_Total)\% Processor Performance` × base clock = current speed, `\GPU Engine(*)\Utilization Percentage`, `\GPU Adapter Memory(*)\Dedicated/Shared Usage`, `\PhysicalDisk(*)\...` incl. `Avg. Disk sec/Transfer`, standby + modified lists = "Cached"); `K32GetPerformanceInfo` (processes, threads, handles, commit, pools - one call); `GlobalMemoryStatusEx`; `GetSystemPowerStatus`; `NetworkInterface` (rates, addresses); DirectX `IDXGIFactory1.EnumAdapters1` (GPU names, LUIDs, dedicated/shared sizes; skip software adapters). No `PerformanceCounter` (extra package on .NET 8+).
- **Match GPUs to counters by LUID** (`0x{high:X8}_0x{low:X8}`), never by position: WMI's order isn't the counters' order, and dropping idle cards shifted every name. Keep idle cards. Load = busiest engine after adding up each process's use per engine, capped at 100. Show Task Manager's four engines (3D, Copy, Video Encode, Video Decode) plus any other while busy.
- Sort drives by number, not by display text ("Disk 10" sorted before "Disk 2"). Sort adapters by name so the list doesn't jump as traffic changes.
- **Layout = Task Manager's Performance tab**: a section list on the left (PC, CPU, Memory, Disk N, each adapter, GPU N) with a mini graph and one-line summary; the chosen section on the right with a big gridded graph (percent, or a two-line rate graph: solid receive/read, dashed send/write), live figures (small label, big value) and a "Details" panel of fixed facts. The PC section shows the other sections as clickable tiles instead of a graph. Sections are built by a pure `BuildSections(snapshot, specs)` with stable ids, and the page syncs lists in place (`SyncList`, `SyncStats`, `SyncBars`) so nothing flickers and the selection stays.
- Specs come from WMI once, off the UI thread, with placeholder values ("To Be Filled By O.E.M.") dropped. WMI returns boxed UInt16/UInt32: unbox before comparing. Virtualization is on when `HypervisorPresent` is true even if the firmware flag reads false. Drive type and bus from `MSFT_PhysicalDisk` keyed by `DeviceId` (= the "Disk N" number). Leave out facts that came back empty rather than showing blanks.
- Reports cover every section and leave out serial numbers and IP addresses (they get pasted into forums).
- Usage warning levels: amber 80%, red 95%. One-minute history per graph (`SystemMonitorManager.History`), drawn by `Controls/SystemMonitorSparkline` (OnRender, cheap; `Values2` for a second dashed line, `ShowGrid` for the big graph). Reading stops when the page isn't shown.
- `StringFormat` does nothing on a `ToolTip` binding (ToolTip is object, not string); expose a ready-made text property instead.

## Network adapters (learned on Network Tools)
- List **every** adapter, not just the ones that are up: `Win32_NetworkAdapter WHERE NetConnectionID IS NOT NULL` includes unplugged and disabled ones (USB Ethernet, docks); join to `NetworkInterface` by GUID (`nic.Id`) for live addresses; read `HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{GUID}` (no admin needed) for what's stored - `EnableDHCP`, `IPAddress`/`SubnetMask`/`DefaultGateway`, and `NameServer` (empty = automatic DNS). Fall back to the live list when WMI fails.
- Tell USB adapters apart by `PNPDeviceID` starting `USB\`; hide virtual ones (PhysicalAdapter false, `ROOT\`/`SWD\` PnP ids, Hyper-V/VPN/TAP/Wi-Fi Direct names) behind a "Show virtual adapters" option. Order: connected (the one with a gateway first), connecting, unplugged, disabled.
- Changes go through netsh as **one script** (`netsh -f file`), elevated with `Verb = "runas"` through `cmd /s /c ... > out 2>&1` so the output can be read back; already admin = run directly. Error 1223 = the user said No: "nothing changed", not an error. netsh sometimes exits 0 on failure - any text other than "Ok." is the reason. Delete the temp files.
- Validate before applying: four decimal parts (`IPAddress.TryParse` takes "192.168.1" as 192.168.0.1 and reads "010" as octal), contiguous mask (dotted or prefix), not the network/broadcast address, gateway on the same subnet and not the PC itself, manual IP needs manual DNS. Send netsh the normalised address. Never pass a name containing a quote.
- Confirm before changing or disabling the adapter that carries the internet (it has a gateway). Fill the edit form from stored settings so it works for unplugged/disabled adapters; never overwrite an open form on auto-refresh.
- Refresh on `NetworkChange.NetworkAddressChanged` / `NetworkAvailabilityChanged`, debounced (~1 s) and only while the view shows (else mark stale). These events are static: unhook in Unloaded and on close.

## Comparing two files (learned on File Differences)
- Diff with Myers (linear-space middle snake, ranges on an explicit stack), after dropping lines that only occur on one side - they can never match, and dropping them turns "two completely different 100,000-line files" from 10^10 steps into one pass. The old LCS table needed n×m cells. Tested for validity and minimality against a brute-force LCS on 20,000 random inputs, and every generated patch must apply back to file B.
- Compare once, project many times: the result holds every row; "Hide unchanged lines" and opening a "⋯ 120 unchanged lines" gap are a projection over it (no re-diff). Ignore options re-diff the files already read (no disk). Only Compare / F5 re-reads the disk, so edits saved elsewhere show up.
- Side by side pairs a block's removed and added lines in order (GitHub's split view); paired lines get word highlights (words, runs of spaces and single symbols diffed with the same matcher) on the stronger `DiffAddedStrongBg` / `DiffRemovedStrongBg` tokens. Skip word highlights when the lines share under a quarter of their text - it's just a different line.
- Line endings, encodings and a missing final line break aren't line changes: report them as notes in an info banner, never as red/green rows. "No differences" with ignore options on says the options hid something.
- Binary or over-size files are compared byte for byte (hash, then the first differing offset), with a verdict instead of an empty list.
- Long lines wrap (no horizontal scroll) so both halves of a side-by-side row keep the same width; screen text is capped at 2,000 characters per line, exports keep the full line.

## Hardware tests (learned on Keyboard & Mouse, Monitor, Game Controller and Audio Output tests)
- **Read devices at the lowest level, away from the UI thread.** Mouse and keyboard come from Raw Input on a thread with its own message-only window (`RegisterRawInputDevices`, `RIDEV_INPUTSINK`), timestamped with the stopwatch the moment they arrive; controllers are polled about every millisecond on their own thread (`timeBeginPeriod(1)`). The UI reads the latest state on a timer. Anything timed on the UI thread blurs polling rates and jitter.
- **Only read what is meant for this program, and only while the page shows.** The listener checks that a window of this process has the focus (cached for 100 ms: the check is the costly part at 8 kHz), the page turns it off and releases keys/buttons/motors when it is hidden or the window is deactivated (a key released in another window would otherwise stay "held"), and `CancelActiveRun` disposes everything.
- **Identify keys by scan code**, with `E0-` for extended keys, so the map is right for any language layout. Ignore Windows' fake shift codes (`E0-2A`, `E0-36`) and the second half of Pause, and treat a repeat of a key already down as auto-repeat, not a press.
- **Say what a measurement is.** Polling rate is the middle interval of the report gaps (a few late reports don't drag it down; gaps over 50 ms are the hand stopping); DPI uses raw counts so Windows' pointer speed doesn't matter and is stopped with a key, because moving to a Stop button adds distance; reaction time is the person plus the whole chain, for comparing devices, not a latency figure; refresh rate waits on `DwmFlush` so it measures the compositor, not what the program draws. Each shows its limits on screen.
- **Test pictures are laid out in device pixels** (`PxRect`), so a 1-pixel line is one pixel at any Windows scaling, with edge mode Aliased and nearest-neighbour scaling; ramps draw one column per step so banding isn't smoothed away. The full-screen window is placed with `SetWindowPos` on the screen's exact pixel bounds, not with DIP maths.
- **Anything that flashes needs a warning.** A flashing picture, or a slideshow that will reach one, asks for confirmation first (photosensitive epilepsy); it is marked on its tile.
- **Sound tests start quiet and never pop.** The level slider tops out at -6 dBFS with a safety line, the generator caps amplitude at -3 dBFS, and every start and stop goes through a 30 ms fade. The stream opens in shared mode at the device's own mix format (no resampling), and playing stops when the page is left. A saved level is clamped on load. To check a device without making sound, run the generator at -60 dB and read its meter.
- **A wrong `PackIcon Kind="Name"` string fails only when the view is created**: `MainWindow.Open` shows a modal "couldn't be opened" box, which hangs an automated run. After writing XAML, check every icon name against `Enum.GetNames<PackIconKind>()` (a scratch console project with the MaterialDesignThemes package does it in seconds); `{x:Static ...PackIconKind.X}` is checked by the compiler, the plain string form is not.
- **Test input handling with harmless synthetic input only.** `SendInput` events reach every program, so a test may send a key with a spare scan code (0x64, F13) and mouse moves of +/-1 px that net to zero, never clicks or common keys. Give listeners a `RequireForeground` switch so a console test can run them.

## Learned on Event Log Explorer

- Backend `EventExplorerManager.cs` (XPath builder, Event ID filter, CSV/JSON, settings) is plain logic; `.Windows.cs` holds `EventLogSession` / `EventLogReader`. Both were run against the real logs from a scratch console project (add `UseWindowsForms` there so `System.Diagnostics.EventLog` resolves).
- Windows' XPath subset has **no `not()`**: leave an Event ID out with `EventID!=N` (a range: `(EventID<a or EventID>b)`). With `TolerateQueryErrors = true` a bad query returns zero events and no error, so check the XPath against a real log.
- `TolerateQueryErrors` also hides an unreadable or missing log: call `GetLogInformation` first so access-denied / not-found surface (`AccessDenied` → show `ElevationBannerCard` + an empty state, not a blank list).
- `UiMotion.FadeVisibility(x, false)` followed at once by `(x, true)` used to leave `x` collapsed when the fade-out finished (a list cleared and refilled looked empty). A show now cancels a pending fade-out; still guard heavy `CollectionChanged` handlers with a `_reordering` flag when you clear and refill.
- A `TextBox` inside a `Grid` row keeps the default style's fixed `Height`: set `Height="Auto"` + `VerticalAlignment="Stretch"` for a code/XML viewer.
- Log names such as `Microsoft-Windows-X/Operational` repeat their last part everywhere: show the whole path (`X › Operational`), not the last segment.

## Generating fake data (learned on Mock Data Generator)
- The default `TextBox` style is fixed at `Height="30"` with vertically centred, hidden-scrollbar content. A multi-line preview must use `CodeTextBoxNoWrap` (or `CodeTextBox`), or it shows one line and looks squashed. Inputs inside an `InputBarStyle` border use `BareTextBox`, which already resets the height.
- The themed `ComboBox` shows its selected value without honouring `DisplayMemberPath`, so a list of records shows the record's `ToString()`. Give it an `ItemTemplate` with a `TextBlock` instead.
- Seeded output must not depend on `System.Random` (its numbers can change between .NET versions). Use a small own generator (SplitMix64) and give every column its own stream, so editing one column never reshuffles the others. One "person" per row feeds the name, e-mail and user-name columns so they match.
- Fake e-mails, web addresses and IPs use the ranges reserved for examples (`example.com`, `192.0.2.x`, `198.51.100.x`, `203.0.113.x`): test data must never reach a real person.
- The preview is the first rows of the real output (same writer, same seed). It redraws about 350 ms after the last change; per-column problems go on the column's own row, the rest in one line above the list.
- A number box that can be cleared or half-typed binds to a forgiving text property (empty = 0, over the limit = the limit) and tidies itself in `LostFocus`. Binding it straight to an `int` leaves it in a conversion-error state while typing.
- Large exports stream to a hidden `.{name}.creating-{id}.tmp` and are renamed at the end; cancel leaves nothing behind. CSV gets a UTF-8 byte-order mark (Excel needs it for accents), JSON and SQL do not. SQL names stay bare when they are plain identifiers (works in every database) and are quoted otherwise.
- A page that holds several tall cards scrolls as a whole (cards get a `MinHeight` / `MaxHeight`) instead of sharing the leftover height with star rows, which squeezed the preview.

## Dates, times and zones (learned on Date & Time Toolkit)
- Pass "now" and the culture into the logic instead of reading them inside it, so every result is tested on fixed dates. The view passes `CultureInfo.CurrentCulture` (the language manager sets it for the UI thread) and `DateTimeOffset.UtcNow`.
- A typed number is a Unix timestamp; the unit is guessed from its size (seconds below 1e11, then milliseconds, microseconds, nanoseconds) and can be forced. A millisecond value before March 1973 reads as seconds, which is why the unit can be chosen by hand. Use `decimal` for the maths: nanosecond timestamps lose digits in a `double`.
- Dates read with `DateTimeOffset.TryParse` using the app's culture first, then the invariant one. A text that carries its own zone or offset keeps it; otherwise it counts as the PC's time or UTC, as the sidebar says.
- A clock time typed for a zone can not exist (the clocks jump forward) or happen twice (they go back). Say so (`InvalidTime`, ambiguous note) instead of silently picking one; the first (standard-time) reading is used for the ambiguous case.
- Count calendar differences from the start date in whole months, then split into years and months. Counting years first and months from a year-shifted copy overflows after a 29 Feb (it gave "23 years 12 months").
- Month and year arithmetic clamps to the last day of the month (31 Jan + 1 month = 29 Feb). Business days skip Saturday and Sunday and, when "skip my non-working event days" is on, the event days marked non-working in Settings > Event days (each date counted once; a repeating event ignores its year, and 29 Feb falls on the 28th in common years). Cap the amounts so a huge value returns "out of range" instead of looping or throwing.
- Zone cards update in place while the clock ticks (replace an item only when the record changed) instead of rebuilding the list every second. The clock only drives the cards while no time has been typed.
- Windows zone names are in the PC's language, with a "(UTC-05:00) " prefix; show the name without it and put the offset in its own pill.
- Event days and holidays live in `AppSettingsStore.EventDays` (settings.json, shared by tools). The toolkit turns the readable ones into plain `DateToolEvent` records, so the logic never touches Settings; it re-reads them every time the page is shown.
- ISO 8601 and RFC 3339 are checked separately and each failure has its own code (`IsoProblem_*` strings): ISO wants a capital `T` and `Z`, no mixing of basic (`20240305T1430`) and extended (`2024-03-05T14:30`) forms, and no time after a reduced date; RFC 3339 wants `YYYY-MM-DD`, extended time with seconds, a dot fraction, hour 00-23 and an offset with a colon (`Z` or `+hh:mm`). `24:00:00` is valid ISO (end of the day) and a leap second `:60` is accepted and shown as the first second of the next minute. Without an offset the time is read as UTC and the page says so.
- Week numbers: ISO (Monday first, week 1 holds the first Thursday; a year has 52 or 53 weeks and early January can belong to the old year's week 52/53), US (Sunday first, week 1 holds 1 January) and the PC's own culture rule are all shown, because they disagree around New Year.
- A grid of cards that should use the whole page is a `UniformGrid` whose column count is set from the measured width (about 250 px per card, never more than there are cards), inside a `ScrollViewer` whose content gets `MinHeight` = the viewport height so the rows stretch. Big numbers go in a `Viewbox` so they grow with the card. Do not use a `WrapPanel` with a fixed card width: it leaves a blank band on the right and below.
- Do not leave a mode bare: give each one a "Good to know" card (`Controls/InfoFact` items in a 2-column `UniformGrid`, a non-shared `x:Shared="False"` resource so the card can sit in both the empty and the result state). Facts say what the thing is and how it works, with EN+ES strings `Str_DateTimeTool_Fact_<Mode><N>_T/_B`. Put the empty-state hint inside the same scroller as the card, not in a sibling that hides it.

## Editing audio (learned on Audio Trimmer & Joiner)
- Layout (same shape as Audio Replay): waveform fills the centre; Clips and Export share one `CardStyle` panel (340 px) on the right behind a slim `PanelToggleButtonStyle` chevron strip (collapses to 0, state saved as `ClipsCollapsed`, hidden below 1000 px wide). Adding clips re-opens it so new work is never hidden. Under the waveform: time readout, then the Replay controller row - trim chip (start / end / length) | pill transport dock (`TransportButtonStyle`, `PlayPauseButtonStyle`) | zoom chip (`ControlChipStyle`).
- Edit non-destructively: a clip is only "this part of that file" (`AudioTrimClip` = source + start + end). Trim, cut and split change a few numbers, so undo is a list of snapshots and costs nothing. Only Export reads and writes audio. Cutting the middle out of a clip leaves two clips; trimming can win back audio that was cut off earlier because the waveform always shows the whole file with the unused part dimmed.
- Draw the waveform from ffmpeg, not from a codec library: decode to 8 kHz mono, keep the loudest sample of every 1/250 s as one byte. Any format ffmpeg reads gets a waveform, one hour is about 0.9 MB, and the work is streaming (read stdout and stderr at the same time). Quiet files get a "Boost view" (drawn taller, sound unchanged), otherwise a -30 dB file looks flat.
- A custom waveform control caches its outline (a single filled geometry, the loudest slice under each pixel column) and redraws only the playhead, selection and ruler while playing. Colours come in as brush properties bound to theme tokens in XAML; never read resources inside `OnRender`.
- Export is one ffmpeg filter graph: input seeking per clip (`-ss -t` before `-i`), `aformat` to one common rate / channel layout, a 5 ms fade where two pieces meet (a cut in the middle of a wave clicks without it), `concat`, then the fades of the whole result and the level step. Fades are clamped so in + out never exceed the length.
- Peak normalize measures first (the same graph ending in `volumedetect`, parsed from stderr) and then applies the exact gain that puts the loudest point at -1 dB. Gain is limited to +40 dB so near-silence is not blown up; a silent result is left alone and says so. Loudness normalize uses `loudnorm` (-16 LUFS), which works at 192 kHz internally, so the rate is set again right after it.
- Output goes to a hidden `.{name}.creating-{id}.tmp` and is renamed at the end; cancel kills the process tree and leaves nothing. The result can never replace one of its own source files. Opus is always 48 kHz; MP3 and Ogg are capped at 48 kHz.
- The preview is NAudio, always 44.1 kHz stereo float, one file open at a time, resampled and mono-to-stereo converted per clip, with the whole-result fades applied to the joined stream (they can span several clips). It plays cuts and fades but not normalization (say so in the sidebar). Formats Windows can not play (ogg, opus, ...) get a converted WAV in `%TEMP%\Smart Tools\Audio Trimmer`, swept on start and on close. Read the position from a 30 ms UI timer, never from the audio thread.
- A mono source upmixed to stereo by ffmpeg (`-ac 2`) is 3 dB quieter. Account for it when asserting levels in tests.

## Testing a view without a screen (learned on Audio Trimmer, Mock Data and Date & Time)
- Host a view in an invisible `HwndSource` (window style 0), set its size, call `Measure` / `Arrange` / `UpdateLayout`, then render it with `RenderTargetBitmap` to a PNG and look at it. No window is shown and nothing is sent to the real screen or mouse. Install a `DispatcherSynchronizationContext` first, or `await` continuations resume on the thread pool and touch the UI from the wrong thread.
- Create a view AFTER switching theme or language: resources are looked up when the view is created, so swapping dictionaries under an existing view shows the old look.
- Build the harness against the built `SmartTools.dll` and resolve the other assemblies from the app's bin folder at run time. Views read and write the real settings files in `%AppData%\Smart Tools`, so check their timestamps afterwards (or avoid anything that triggers a save).
- This found a bug no unit test could: the themed `TextBox` template reserves about 24 px inside its scroll area. A box narrower than padding + 24 + the text shows nothing at all (it looked like "cannot be edited"). Keep small number boxes at least about 90 px wide, and put units such as "%" in their own column instead of padding the box.

### Learned on Monitor HDR & Color Depth Checker
- **Call DXGI through its vtable, and count the slots.** `IDXGIOutput6.GetDesc1` is vtable slot 27 (IUnknown 0-2, IDXGIObject 3-6, IDXGIOutput 7-18, Output1 19-22, Output2-5 one each 23-26); a slot off by one reads a different method and quietly returns nothing. Check against the real machine: the numbers (primaries, nits) must be non-zero.
- **HDR comes from two places**: display config (advanced colour, `DISPLAYCONFIG_DEVICE_INFO_GET_ADVANCED_COLOR_INFO_2` on Windows 11 24H2, the older type 9 otherwise) and DXGI colour space (12 = HDR10, 10 = scRGB). Match them by GDI name (`\.\DISPLAY1`). DXGI reports EDID luminance even on SDR screens, so show brightness only when HDR is supported.
- **"Maximum bit depth" is the EDID byte 0x14** (digital inputs), found through the monitor device path in `HKLM\SYSTEM\CurrentControlSetnum\DISPLAY`. Say "not reported" when it is missing instead of guessing.
- **WPF draws 8-bit SDR**, so the pictures cannot show a 10-bit gradient or the real HDR peak. Say so on the page; the white-window picture shows brightness limiting, not peak nits.

## Encoding and decoding text (learned on Base64 & URL Encoder / Decoder)
- Never throw at the user: every conversion returns a result with a problem code, the 0-based index and the offending character, and the view turns the code into a sentence (`Str_EncTool_Problem_<Code>`, with the position as {0} and the character as {1}). Notes that are not errors (padding was missing, URL-safe alphabet, bytes are not text) are separate codes (`Str_EncTool_Note_<Code>`).
- Be generous reading, strict writing: Base64 decoding accepts both alphabets, missing padding, spaces, line breaks and a `data:...;base64,` prefix, but rejects a mixed alphabet, data after `=` and a leftover single character, each with its own message. Writing follows the sidebar exactly.
- Text goes through bytes: the text encoding (UTF-8, UTF-16, Latin-1) is explicit, decoded bytes are checked strictly, and bytes that are not valid text or look binary (NUL and control bytes) are never dumped into a TextBox. The page shows a file panel (known type from magic bytes, size, Save as file) instead, and Save writes the exact decoded bytes.
- Percent encoding works on bytes, one surrogate pair at a time. "Full URL" keeps `:/?#[]@!$&'()*+,;=` and any real `%XX` (so `%20` is not turned into `%2520`); "Component" keeps only unreserved characters. Space as `+` is one option for both directions, because the same people need both.
- Settings that only apply to one direction are disabled, not hidden, with the reason in the hint. The conversion is debounced (~150 ms), runs inline under 20,000 characters and on a worker above that, and a newer request makes the older result get dropped (`_runId`).
- Only the first 200,000 characters are put in a TextBox (a note says so); Copy and Save use the whole result. Files are capped at 30 MB (Base64 adds a third) and text at 5 million characters.
- Layout lesson: a row with a fixed-width toggle plus buttons clips in a 760 px window. Put the right-hand group in its own panel and move it to a second row in `SizeChanged`.
- Test harness lesson: the real settings file is shared by every scenario in a headless render run, so delete it before each scenario or the previous scenario's mode leaks into the next picture.

## Drawing tools (learned on Pixel Art Editor)
- Colours are packed ARGB in a `uint` and fully transparent is always exactly 0 (`Normalize`), so "empty" is one comparison and a see-through colour can never be confused with the eraser. The opacity bar stops at 1 for the same reason.
- Record edits as data: a stroke is a list of changed pixels (index, old, new) taken from the first value each pixel had, so painting over and back again is not an edit and a 256 x 256 picture costs almost nothing per step. Whole-picture changes (resize, turn, frames) are snapshots. Undo and redo only work if they are strictly last-in-first-out; frame arrays can be shared between a snapshot and the next one for that reason.
- Draw the line between two pointer positions, not just the point under the pointer, or a fast drag leaves gaps. Shapes show a ghost while dragging and become one edit on release; Esc cancels.
- An ellipse is the pixels whose centre is inside it, and its outline is the inside pixels that touch an outside pixel. That is always closed and symmetric. A very thin ellipse (16 x 2) misses the ends of its box, so every column and row without a pixel gets the middle one(s), both when the size is even.
- The picture control draws at a whole-number zoom with nearest neighbour and aliased edges, writes the pixels straight into a `WriteableBitmap` (a `uint` ARGB array is already Bgra32), keeps the checkerboard, grid and mirror guides as brush properties bound to theme tokens, and owns no editing logic. Grid lines are drawn at about 35 % opacity or they overpower the art.
- Fit picks the biggest whole zoom that shows the whole picture, and keeps fitting while the window resizes until the user zooms by hand.
- The artwork is only in memory, so ask before throwing it away (New canvas, Open picture) when it has not been exported. Settings hold the setup and the user's own colours, never the drawing or a path.
- A colour box that takes typed hex must not rewrite the text while it has the focus: #00F is a valid colour on the way to #00FF00. Show the error under the box and put a readable form back on LostFocus.
- Typing a code is not a way to make a colour. A colour mixer (saturation / brightness square, hue bar, opacity bar) goes next to the hex box, and the two follow each other. The mixer keeps its own hue when the colour has none (black, white, grey), or the hue bar jumps to red every time. Reuse `ColorManager.HsvToRgb` / `RgbToHsv`.
- Export a PNG with a small hand-written writer (`PngWriter`): 8-bit RGBA, one IDAT, tested by decoding the result with WPF's own decoder on random pictures. Enlarge by whole numbers only, refuse over 8192 px with a code, and say the exact size before the file is made.
- A `Button` inherits the app-wide fixed height. A button used as a thumbnail or card template needs `Height="Auto"` and `MinHeight="0"`, or its content is clipped to a thin strip.
- A bar of controls that can be narrower than its contents (direction row, export row) moves its right-hand group to a second row in `SizeChanged`, and a fixed-width `UniformGrid` inside a `WrapPanel` gets clipped instead of wrapping, so give it its own row.
- Testing a view that calls private methods: a harness can reach them with reflection, but `dynamic` cannot bind an `object`-typed enum argument. Use `MethodInfo.Invoke` with boxed values.
- Colours the user saved in one tool are offered in the others. The Color Picker's Favorites live in `color_history.json` (`ColorHistoryStore`, also read by Screen Color Picker); Pixel Art shows them as a read-only "Favorites (Color Picker)" palette and reloads the file every time the page is shown, so a favourite added a moment ago is already there. Share through the store class, never a second copy of the file format, and keep the other tool's list read only unless it is the tool's own job to edit it.

## Packing and cutting pictures (learned on Sprite Sheet Packer)
- Pack with MaxRects (best short side): biggest sprites first, ties by index, so the same inputs always give the same sheets. Reserve the padding by packing into a bin that is `padding` bigger and placing each sprite `padding` bigger; then a sprite exactly as big as the biggest sheet still fits and nothing needs trailing padding. Prove it on random sets: every sprite placed once, inside the sheet, at least `padding` apart, sheet sides powers of two (or exactly the used box when that is off).
- Find the smallest sheet by trying the power-of-two sizes from small to big (by area, then squarest). Fill the biggest sheet first to decide which sprites share it, then shrink that sheet to the smallest size that holds them. A sprite bigger than the biggest allowed sheet is reported, not dropped silently.
- Trim by alpha and keep the offset: the coordinates file carries the trim offset and the source size, or trimming moves things in the game. A completely see-through picture keeps one pixel instead of a zero-size box.
- Coordinate files are written by real writers (`Utf8JsonWriter`, `XmlWriter`), never by string concatenation of names; names are made safe (letters, digits, - and _) and made unique (-2, -3). CSS uses `0` for a zero offset, never `-0px`.
- A packed set is more than one file (several sheets and the coordinates). Pick one name for the whole set that is free for every file, write each through a hidden temporary name, and if anything fails remove what this run wrote, so a set is never half old and half new. When the user chose "replace" in the Save dialog, that is the only time a name may be reused.
- The preview is the real thing: the same compose function that saves the file draws the preview, from the same cached pixels, so what is shown is what is saved. Decoded pictures are cached by path, size and date (with a memory cap) so changing padding or the sheet size repacks without reading the disk, and the work runs off the UI thread with a counter that drops a superseded result.
- Show a preview of a big picture inside a `Viewbox` directly in its card, not inside a `ScrollViewer`: a scroll viewer gives its content infinite space, so the box stays at 100 % and a 2048 px sheet overflows while a small one stays tiny. Draw hover and selection rectangles on a `Canvas` over the picture in picture pixels, with the stroke thickness divided by the Viewbox scale so it stays about 2 px.
- Slicing: the grid comes from pure maths (by count or by cell size, with margin and spacing) that also reports the leftover pixels and refuses impossible grids with a code (cell too small or too big, too many cells). Draw the cells as one geometry over the picture and dim the cells that will be skipped. Name the files `prefix_01` padded to the number of cells, put them in a new folder (never into an existing one), count a failed file and carry on, and let Stop keep what was written.
- One shared Output card serves both modes: file mode (name of the sheet) for packing, folder only for the frames, switched with `ShowFileName`.

## Marking many kinds of files (learned on Batch Watermarker)
- Draw the mark once, as a transparent picture, and let every engine lay that same picture over its kind of file (ImageMagick composite, a picture drawn on each PDF page, ffmpeg `overlay`). The preview, the pictures, the pages and the videos then look alike, and the look is written and tested in one place. Draw only the area the copies cover (a single corner mark is a small picture, a tiled one covers the file) and say where that area starts.
- Sizes are shares of each file (text height of the shorter side, logo width of the width), never pixels, or one setup is invisible on a 4K video and huge on a thumbnail. Keep a floor (text never under 6 px) and a cap (a logo never wider than the file).
- Tiled marks are one lattice in brick rows, turned about the file's centre by the mark's own angle, keeping only the copies that touch the file, with a hard cap on copies so a tiny mark on a huge file can't make millions. Place single marks by the grid cell, inside the margin, with the centre ignoring the margin and a mark too big for the margin centred on that axis. Prove the maths on fixed sizes without WPF.
- PDF pages differ: size, `/Rotate` (0, 90, 180, 270) and the crop box. Draw the stamp for the page as it is shown, then turn it back into the page's own space with a matrix per rotation; shift by the crop box. Test by rendering the result with Windows' own PDF renderer (`Windows.Data.Pdf`) on a document with portrait, landscape, rotated and cropped pages, and look at it.
- PDFsharp quirk: reading `page.CropBox` on a page that has none creates the entry and changes the page (pages came out the wrong shape, content clipped). Check `page.Elements.ContainsKey("/CropBox")` before reading it, and compare the pages before and after.
- A WinRT call awaited from the UI thread of a test harness deadlocks (the continuation needs the thread you are blocking); run it with `Task.Run`.
- Videos are re-encoded, so say so: H.264 CRF 18, even dimensions (`scale=trunc(iw/2)*2:trunc(ih/2)*2`, a 641 x 361 source would otherwise fail), 8-bit 4:2:0, sound copied when the container can hold that codec (otherwise AAC), MP4 unless the source is already MP4 / MOV / M4V / MKV. Probe the size after rotation (phone videos) because ffmpeg turns the picture upright. Use the shared `ConverterManager.RunFfmpegAsync` for progress, cancel and the hung-process timeout.
- Batches mix kinds: give each kind its own concurrency (pictures and PDFs two at a time, videos one), post item status back to the UI context, isolate each file's failure with a plain-words reason on its row, and when Stop is pressed remove only the file in progress (hidden `.name.creating-id.tmp`) and keep the finished ones. Choose the result name and move the file under one lock so two files can't be given the same free name.
- A preset that uses a logo must not point at the user's file: copy the logo into the app's folder under an app-made name, store only that name (and refuse anything with a path in it when loading), and remove copies nothing uses any more.
- Normalize every loaded setting (clamp numbers, fall back from a bad colour, drop built-in or duplicate preset names) so a damaged file or hand-edited preset can't break drawing. Any change of the look turns the preset selector to "Custom", so what is shown is never labelled with a preset it no longer matches.
- The preview of a file that can't be drawn (damaged picture, password-protected PDF) still shows the mark on a blank page of a believable shape, with the reason in the note, instead of going empty.

## Keyboard shortcuts (learned on Shortcuts)

- A view never checks chords itself: define the action in `ShortcutManager`'s static constructor (id, `Str_Shortcut_*` title, default chord, owner tool id) and call `ShortcutManager.Attach(id, handler)` once in the view's constructor. `MainWindow.Window_PreviewKeyDown` runs the action of the page shown, so a tool's keys never fire on another page. Bare keys (arrows, Del, Esc, typing keys) can stay in the view's own `PreviewKeyDown`.
- Plain letters are ignored while a text box has the focus; chords with Ctrl/Alt/Win and F-keys still run.
- Global keys use `RegisterHotKey` on a message-only `HwndSource`; they need Ctrl, Alt or Win. Release them when the app exits, and while a `KeyRecorderBox` has the focus (otherwise Windows eats the key before it can be recorded).
- A key another program owns is a warning on that row, never an exception. Only keys that differ from the default are saved in `settings.json`, by action id.
- Tooltips that mention a key should read it from `ShortcutManager.ChordText(id)` so they follow a rebind.

## Floating widgets and MAC manufacturers (learned on Network Speed Widget)
- A widget is a tool page (options + live preview) that **owns** one borderless `Topmost` window (`Controllers/NetworkSpeedWidgetWindow.cs`, `ShowInTaskbar=false`, `AllowsTransparency`, `SizeToContent`). The window only displays; numbers come from the manager. Its colours are theme tokens set with `SetResourceReference`.
- Do **not** set `Owner` to the main window: owned windows minimize with it, and the widget should stay visible. Close it from the view's `CancelActiveRun()` (wired in `RegisterTools()`), and also when the user hides it, so it can never outlive the app. Close-to-tray returns early from `Window_Closing`, so the widget keeps running then.
- Click-through = `WS_EX_TRANSPARENT` set with `SetWindowLong` once the handle exists (re-apply on `Loaded`). Once on, the widget can't be clicked - the page must hold the switch to turn it off (say so in the hint text).
- Remember the position, but check it is still on a screen (`SystemParameters.VirtualScreen*`) before using it; otherwise snap to the work-area corner.
- Rates: `GetIPStatistics()` byte counters on a timer; a counter that went down (reset / adapter swap) counts as 0 for that tick; drop remembered counters of adapters that vanished; an adapter chosen earlier that is gone falls back to "all active". `System.Threading.Timer` is ambiguous with WinForms' - alias it.
- Manufacturer: `Controllers/OuiLookupManager.Shared.Lookup(mac)` (any separator). Data is the bundled IEEE snapshot `Data/oui.txt` (`PREFIX<TAB>Name`, ~40k lines, copied to the output by a `<Content>` item). Locally administered MACs (bit 0x02 of the first byte) return "Private (randomized)" - never a manufacturer. Load it once, off the UI thread (`Task.Run(() => OuiLookupManager.Shared.IsAvailable)`) before the first lookup-heavy view.
- To refresh the list: `https://standards-oui.ieee.org/oui/oui.csv` answers HTTP 418 to a plain scripted request; `oui.txt` from the same site works. Regenerate `Data/oui.txt` from lines like `00-1A-11   (hex)\t\tGoogle, Inc.`.

## Learned on Background Remover — edge halo

- ImageMagick `Transparent()` + `ColorFuzz` is a hard 0/255 key that never touches colour, so anti-aliased/JPEG edge pixels kept a white/black fringe that showed on any new backdrop. `BackgroundRemoverManager.KeyOutColor` now uses a soft "colour to alpha" matte (alpha ramps from Tolerance to Tolerance + Edge softness) and un-mixes the key colour from partly transparent pixels (`C = K + (P - K) / alpha`). Optional Edge choke erodes the alpha 0-3 px, in whole pixels (a 0.5 px disk is a single pixel, i.e. a no-op). "Clean edges" off = the old hard key.
- Trade-off: a higher Edge softness makes light subject areas on a white key (or dark ones on black) translucent — keep the default moderate.

## Learned on the Colors tools — favorites, exports, hex fields

- Favorites live in one place, `ColorHistoryStore` (`color_history.json`). Color Picker, Screen Color Picker, Color Wheel and Palette Extractor all read/write it; each view calls `Load()` in its `Loaded` handler so changes made in another tool show up. Never add a second favorites file.
- Screen Color Picker has no run bar any more: like Color Picker, its actions (Pick, Favorite) sit in the picked-colour card header, as `ListToolPrimaryButtonStyle` buttons. The "primary action top-left run bar" rule is for run/convert tools, not for these live colour tools.
- Color Wheel: one Save button exports a single PNG (wheel + start colour + gradient strip + end colour, with hex labels). Start/End hex fields are stacked full-width in the 280 px sidebar; side-by-side they only had ~40 px of text room and clipped `#RRGGBB`.
- Palette Extractor PNG strip: equal square blocks (6 per row), each with hex and share %, because proportional widths hid small colours.

## Moving a database between server versions (learned on Database Migrator)
- A `.bak` only restores upward, so the tool copies through two live connections instead: structure as generated DDL, data streamed with `SqlBulkCopy` (`SqlDataReader` straight in, `EnableStreaming`, `KeepIdentity | KeepNulls | TableLock`). Never load a whole table into memory. The source gets read-only queries (`ApplicationIntent=ReadOnly`) and is never written to.
- Read the schema from `sys.*` catalog views only (no SMO), gating columns that older servers lack on the major version (`temporal_type` 13+, `ledger_type` 16+, `optimize_for_sequential_key` 15+, `last_used_value` 14+). Azure SQL (engine edition 5 and 8) reports 12.x but behaves like a current server.
- Version rules live in one place (`DbMigrateManager.Compat.cs`): an option the target lacks is left out and reported, a feature that changes meaning is never guessed (the table is skipped and listed), and a version the table doesn't know is treated as "supports it". The data types and T-SQL features lists are best-effort hints; the real test is the CREATE, whose error is logged.
- Order matters: schemas, types, sequences, tables, synonyms, DATA, indexes (clustered first), checks, foreign keys (`WITH CHECK`), views/functions/procedures (retry until a pass makes no progress), indexed-view indexes, triggers (after the data, so they don't fire), identity reseed, descriptions. Indexes and keys come after the load because loading into bare tables is much faster.
- Every DDL connection first runs `SessionSetup` (`ARITHABORT`, `ANSI_WARNINGS`, ...). SqlClient leaves `ARITHABORT` off, and indexed views and computed-column indexes fail without it. Each module also gets its own `SET ANSI_NULLS` / `SET QUOTED_IDENTIFIER` command first, taken from `sys.sql_modules`.
- `CREATE OR ALTER` in a saved definition is rewritten to `CREATE`. `WITH ENCRYPTION` modules can't be read, so they're reported, not copied.
- Plan first, write second: Analyze writes nothing and lists blockers, warnings and skipped tables; Migrate asks one confirm dialog (default No) that says what is created and what is left out, and refuses to run if the servers, databases or options changed after the analysis (the plan signature, passwords left out).
- Only a database this run created is ever dropped, and only when asked (a checkbox, or a Yes on the follow-up dialog that defaults to No). Passwords stay in the password boxes (memory only); `db-migrate.json` keeps servers, database names, sign-in mode and user names.
- One table failing is logged and the rest carry on; row counts are always verified, checksums only on request, and a checksum mismatch with equal row counts is a warning (float and date values can checksum differently between versions).
- Not copied, and said so in the Notes tab: CLR objects and user types, columnstore/XML/spatial indexes, partitioning, full-text, XML schema collections, memory-optimized, temporal, ledger and external tables, DDL triggers, logins, jobs and permissions.
- Testing: the pure half (`.Catalog/.Compat/.Script`) compiles in a plain console project by including the source files directly. The live run was checked against two LocalDB databases (identity, sequences, computed columns, indexed view, table type + procedure, trigger, synonym, cancel, drop).
## Password Vault (learned on `Password Vault`)

Backend: `PasswordVaultManager*.cs` (+ `PasswordVaultWidgetWindow.cs`, `Views/VaultPasswordDialog.cs`). File `%AppData%\Smart Tools\vault.svlt`, settings `password_vault.json` (never a secret).

- **Format `SVLT` v1:** Argon2id (128 MiB, 3 passes, 4 lanes - stored in the header, range-checked on read) -> HKDF-SHA256 -> AES-256-GCM, fresh nonce on every save, the whole header is the AEAD associated data. Wrong password and tampering give the same answer (`WrongPasswordOrTampered`). Argon2 comes from the `Konscious.Security.Cryptography.Argon2` NuGet package - the only crypto package; everything else is `System.Security.Cryptography`.
- **The pure half compiles in a plain `net8.0` project** (`.Crypto.cs`, `.Totp.cs`, `.Io.cs`, the manager, the model; `.Health.cs` needs `PasswordGeneratorManager`, so stub `AnalyzeHealth` there). Keep it that way - the round-trip / tamper / RFC 6238 / CSV / backup checks were run like this.
- **Secrets in memory:** the master password only travels as `char[]` (read from `PasswordBox.SecurePassword`, wiped after use). Entries' passwords are plain `string`s while unlocked - that can't be fixed in .NET, so `Lock()` wipes the key, blanks the entries and every editor field (`ClearEditor`) and says so in the sidebar note. Never put a password in a settings file, a log or a temp file.
- **Layout:** the editor card is collapsed (column width 0) until an entry is opened or created, so the list uses the full width; its X button closes it (asks first if there are unsaved edits). The Save / Delete row is pinned under the scrolling fields.
- **Read-only first:** opening an entry shows it read-only (`SetReadOnly`); copy, reveal, and open-URL still work. The **Edit** button (or right-click > Edit) unlocks the fields and swaps itself for Save; a new entry starts editable, and saving returns to read-only. The right-click menu on a list row (Edit, Copy username, Copy password, Delete) selects the row first so the editor and its status line follow it. Delete goes through `DeleteEntry(id)` for both the menu and the editor button (Undo bar for 8 s).
- **Grouped list:** the first tag of an entry is a path (`Games/Launchers`, up to 4 levels, split on `/` and `\`); the list shows collapsible nested headers with counts, parent entries before sub-groups, and "Ungrouped" last (no header at all when nothing is tagged). `PasswordVaultManager.Groups.cs` is pure (compiles in a plain `net8.0` project). Headers are `VaultGroupRow`s in the same list as the entries but are never selectable (`VaultRowStyle`), so `SelectedItem as VaultEntry` stays valid. Collapsed groups are kept in memory only (tag names are not written anywhere) and cleared on lock; searching or "only problems" expands everything, and saving an entry opens its groups.
- **All lock and clipboard options** (auto-lock time, lock on minimize, lock on Windows lock, clipboard delay) live in Settings > Password vault; the vault sidebar only holds actions. **Auto-lock setting** is saved there (it writes `password_vault.json` and `PasswordVaultManager.SettingsSaved` tells an open vault view to re-read it). The vault list header has a countdown badge ("Locks in m:ss", amber in the last 30 s, "Auto-lock off" for Never).
- **Auto-lock:** idle timer driven by `InputManager.PreProcessInput` (hooked only while unlocked), host window minimized / hidden to the tray, `SystemEvents.SessionSwitch` (unsubscribe on lock - it is a static event), and `CancelActiveRun()` on exit. Idle lock discards unsaved edits on purpose.
- **Unlock throttling:** the delay doubles after each wrong password (0.25 s up to 8 s) and resets on success.
- **Changing the master password** re-derives with a new salt and deletes the `.bak` (it is still locked with the old password).
- **Clipboard:** same three exclusion formats and "clear only if still ours" as Password Generator; delay is a setting (10-120 s).
- **CSV:** export is plain text and warns first; cells starting with `= + - @` get a leading `'` (Excel formulas), removed again on import. Import accepts Bitwarden / Chrome / LastPass column names and skips exact duplicates.
- **Widget:** same shape as the Network Speed widget (borderless, topmost, no Owner, position validated against the virtual screen) plus `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`. While locked it holds no entries at all - only an "open the vault" button. Closing it from its X remembers that; closing the app does not.


## Hosts File Editor, Startup Apps, Clipboard History (learned on the first build of each)

- **Hosts File Editor** (`Tools/Network/HostsEditor/`): `HostsEditorManager.Parse.cs` is pure (compiles in a plain `net8.0` project). Lines the user didn't touch are written back byte for byte (`HostsRow.Raw`, `Modified`); only edited entries are rebuilt. A line like `# 10.0.0.5 name` is an entry that is switched off, so the stock sample lines in Windows' hosts file show up as off entries. Every save copies the old file to `%AppData%\Smart Tools\hosts-backups` (newest 10) and writes in place so the file keeps its permissions. Saving needs administrator rights: the view shows a banner with "Restart as administrator" (`AppRestartManager.StartElevatedCopy`, same flow as Hardware Sensors).
- **Startup Apps** (`Tools/Performance/StartupApps/`): lists Run keys (user, all users, 32-bit) and both Startup folders. On/off is the same flag Task Manager uses (`...\Explorer\StartupApproved\Run|Run32|StartupFolder`, 12 bytes, even first byte = on), so the two always agree; the entry itself is not touched. Remove deletes the Run value or the Startup file. Entries for all users need administrator rights. Scheduled tasks are not listed.
- **Services** (`Tools/Performance/Services/`): reads `Win32_Service` through WMI and the "who depends on whom" links from `Win32_DependentService`. Start, stop, pause, and resume are WMI methods; the call returns before the service has finished, so the manager polls while the state is "pending" (30 s) and runs on a background thread while the row is marked `IsBusy`. The startup type goes through `sc.exe config` because WMI's `ChangeStartMode` cannot set "Automatic (delayed)". Windows refuses to stop a service while others depend on it, so Stop and Restart list the running dependents, ask, and stop them first (deepest first); Restart starts them again afterwards. A small list of core services (`CoreServices`) asks a second time before being stopped or disabled. Administrator rights use the shared `ElevationBannerCard`; WMI reports "access denied" for both missing rights and services Windows protects, so the message names both.
- **Clipboard History** (`Tools/Utilities/ClipboardHistory/`): memory only, on purpose, so nothing a user copies is ever written to disk; it is dropped on `CancelActiveRun()`. A hidden message-only window (`AddClipboardFormatListener`) gets `WM_CLIPBOARDUPDATE`; the clipboard can still be locked by the copying program, so reading retries a few times. Copies carrying `ExcludeClipboardContentFromMonitorProcessing` or `CanIncludeInClipboardHistory = 0` (what the Password Vault sets) are skipped.
- **Pattern for display text in models:** models stay language-free, so the view fills a plain string property (`HostsRow.ProblemText`, `StartupApp.SourceText`, `ClipboardItem.MetaText`) before showing the row.
- **Icons:** `Kind="..."` names in XAML are only checked at run time. `BroomOutline` does not exist in this MaterialDesign version (`Broom` does).


## JWT Decoder, JSON / YAML / XML Formatter, Environment Variables, Bulk Image Resizer, Screen Recorder (learned on the first build of each)

- **JWT Decoder** (`Tools/Developer/JwtDecoder/`): fully offline and pure (`JwtDecoderManager` compiles in a plain `net8.0` project). It never verifies a signature (that needs the key) and says so in a pill; `alg: none` is flagged as unsigned. The expiry pill ticks every second from a `DispatcherTimer` that `CancelActiveRun()` stops. Time claims (`exp`, `nbf`, `iat`) outside the DateTimeOffset range are ignored instead of crashing.
- **JSON / YAML / XML Formatter** (`Tools/Developer/DataFormatter/`): every format is read into one `System.Text.Json.Nodes.JsonNode` tree and written back out, so any pair converts. XML maps attributes to `"@name"` keys and mixed text to `"#text"`; YAML comments/anchors, XML comments, and namespace prefixes are dropped (the sidebar says so). **YamlDotNet quirks:** malformed YAML can throw a plain `InvalidOperationException` (not `YamlException`), so it is caught separately; `YamlException.Start.Line` is a `long`; output is written with the `Emitter` directly (the serializer writes `nothing: ` with a trailing space for null). Strings that would read back as another type (`"42"`, `"true"`, `"007"`, `"~"`) are quoted, plain words are not. A `JsonValue` made from XML/YAML holds a CLR string, one parsed from JSON holds a `JsonElement` - always read strings through `StringOf`. Parsing runs on a worker thread with a generation counter so a newer keystroke wins.
- **Environment Variables** (`Tools/Utilities/EnvironmentVariables/`): reads and writes the registry directly (`HKCU\Environment`, `HKLM\SYSTEM\...\Session Manager\Environment`) because `Environment.SetEnvironmentVariable` can't keep an unexpanded `%REF%` or `REG_EXPAND_SZ`; then broadcasts `WM_SETTINGCHANGE`. In-memory undo of the last 20 changes. System scope needs administrator rights (same restart banner as Hosts File Editor). PATH checks (`Analyze`) are pure and take the folder-exists function as a parameter.
- **Bulk Image Resizer** (`Tools/Images/BulkImageResizer/`): Magick.NET directly (Convert Files' image path is private and bound to its own plan type). Output is written to `name.ext.tmp` and moved into place; with parallel workers, file names are reserved under a lock (`ReserveName`), because two pictures with the same name from different folders would otherwise pick the same free name. A target file size searches the quality by halving (`FindQuality`); EXIF rotation is baked in (`AutoOrient`) before the metadata is stripped, and the ICC color profile is kept. Animated and multi-page pictures are skipped with a reason. **Magick.NET 15:** the orientation enum is `ImageMagick.Orientation`, and a JPG only gets an EXIF orientation tag when both the profile and the `Orientation` property are set. The native library failing to load (`TypeInitializationException`/`DllNotFoundException`) is caught and reported per picture.
- **Screen Recorder** (`Tools/Video/ScreenRecorder/`): bundled FFmpeg - `gdigrab` for the picture, `dshow` for a microphone (system sound isn't available), libx264 + AAC. Arguments go through `ArgumentList` (no quoting problems with device names). The file is a fragmented MP4 (`frag_keyframe+empty_moov`), so a crash or a closed app still leaves a playable video. Stopping writes `q` to FFmpeg's stdin and waits; it is only killed after 8 s. `StartAsync` waits 1.2 s to catch FFmpeg exiting at once (a dead window handle), and an `_starting` flag keeps the "ended by itself" handler out of that window (a real race found in testing). Region/screen coordinates are virtual-desktop pixels and can be negative (monitor left of the main one). `ScreenRecorderControlWindow` (the small Stop bar) calls `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`, which is why it has no `AllowsTransparency`. `__COMPAT_LAYER=HighDpiAware` is set for the FFmpeg process so scaled displays don't capture a stretched picture (verified only at 100% scaling).
- **TextBox height:** the global TextBox style sets `Height="32"`. A multi-line box that should fill its cell needs `Height="Auto"` or it collapses to one line in the middle of the card.
- **Placeholder text is the TextBox `Tag`** (the shared template draws it, `BareTextBox` included), not `materialDesign:HintAssist.Hint`, which draws nothing here.
- **List rows that have buttons on the right** need an `ItemContainerStyle` with `HorizontalContentAlignment="Stretch"` (based on `{x:Type ListBoxItem}`), otherwise the buttons float right after the text.
- **Icon names are not checked at compile time** when written as `Kind="Name"` (only `x:Static PackIconKind.Name` is). Check them with `Enum.GetNames(typeof(PackIconKind))` - scanning the DLL bytes gives false "missing" results because short names share storage with longer ones. Example of a name that doesn't exist: `BroomOutline` (use `Broom`).
- **Checking a view really renders:** compile success proves little (a missing key or a bad template only fails at run time). A throwaway WinExe in the scratchpad can reference `SmartTools.dll`, merge `Themes/Light|Dark.xaml`, `Themes/Controls.xaml`, and `Language/en.xaml` (`pack://application:,,,/SmartTools;component/...`), create each view, show it off-screen, fill it with sample data, and `RenderTargetBitmap` it to a PNG. Needed for it to behave like the app: install a `DispatcherSynchronizationContext` first (managers capture `SynchronizationContext.Current`), resolve managed and native dependencies from the app folder, and attach trace listeners to `PresentationTraceSources.DataBindingSource`/`ResourceDictionarySource` to catch missing resources and bad bindings. Build the app into a different `-p:OutDir` when the running app locks `bin\`.

## Unit & Currency Converter, DNS / WHOIS / Traceroute, Text Diff, PDF Extras (learned on the first build of each)

- **Sidebar, always.** `ModeToggleButtonStyle` / `ModeToggleTallStyle` are dark sidebar styles: dropped into a light content card they look like a different app. Put the choice in the 280 px sidebar (`SidebarGroupCardStyle`, collapse button), and keep the content area for the input and the answer. Spanish labels are about 30% longer: a row of three tall toggles clipped "Desbloquear", so six actions sit in two columns. Check every label in `es` with the render harness before calling a layout done.
- **Unit & Currency Converter** (`Tools/Utilities/UnitConverter/`): every unit is `value * ToBase + Offset` into the category's base unit (only temperature has an offset), so one `Convert(value, from, to)` serves all of them and a test round-trips every unit pair. Numbers are shown at 10 significant digits (`0.1 + 0.2` reads `0.3`). **Parsing:** `NumberStyles.AllowThousands` accepts a group separator anywhere, so `1,5` parsed as fifteen in English (and `1.5` in Spanish). A separator only counts as grouping when the digits really are in threes (`GroupingOk`); otherwise a single comma is a decimal comma. Rates come from the free Frankfurter service (European Central Bank data, no key, about 30 currencies, base USD); only the base currency is requested, and the last copy is cached in `currency_rates.json` for offline use, with a pill that says whose date it is. Settings hold the category and units, never a typed number.
- **DNS, WHOIS & Traceroute** (`Tools/Network/DnsTools/`): the DNS client is hand written (`DnsProtocol`, pure, 12 byte header + question; names with compression pointers and a loop guard) so the question can go to a chosen server (Windows', Cloudflare, Google, Quad9, OpenDNS, or an address you type) and answers can be compared. UDP first, one retry (UDP loses packets: Quad9 timed out once in a test run), TCP when the TC bit says the answer didn't fit (`google.com` TXT). Typing an address does a reverse (PTR) lookup. International names go through `IdnMapping`. **Testing NXDOMAIN:** use `.invalid`. Cloudflare answers "no data", not "no such name", for any made-up subdomain of `example.com`.
  - **WHOIS** talks to port 43: ask `whois.iana.org` which server serves the ending (cached for the session), ask that server, follow one `Registrar WHOIS Server:` referral, and keep whichever record has more fields (IANA's own stub for `example.com` is thinner than the registry's). `www.example.com` is tried first, then `example.com` (registries only know registered names). Verisign needs the word `domain ` before the name; DENIC needs `-T dn,ace `. **Regex trap:** in `whois:   ` with nothing after the colon, `\s*` runs across the line break and the next word became a "server" (`status`); use `[ \t]*`. `.uk` and some other endings have no port-43 service (IANA lists an empty `whois:`), which is reported as such, not as a failure. Many records show "REDACTED FOR PRIVACY"; the tool shows what the registry gives.
  - **Traceroute** sends `Ping` with a growing TTL, three probes per hop at once (a silent hop costs 2 s, not 6), and reports each hop as it is known through `IProgress<TraceUpdate>`; router names arrive later as a second update on the same hop (most routers have none). Round trips under 1 ms show `<1 ms`, never `0 ms`. Cancelling keeps the hops found.
  - Settings keep the tool, record type, server and hop limit, never a host name.
- **Text Diff** (`Tools/DataQuality/TextDiff/`): not a second engine. It calls File Differences' public static `FileDifferencesManager.DiffLines`, `Project` and `BuildUnifiedDiff` (and the internal `SplitLines`), draws the same rows with the same templates and `FileDiffTextView.Source` highlight, and reuses its `Str_FileDiff_*` strings. **Keep those signatures stable: both tools depend on them.** The compare runs 350 ms after typing stops, off the UI thread, and a generation counter drops a result that was superseded (60,000 lines take about 70 ms). Line endings and a final line break are not changes (the same rule as File Differences). Texts are never saved; only the view mode and the three checkboxes are.
- **PDF Extras** (`Tools/Convert/PdfExtras/`): rotate pages, remove or keep pages, page numbers, document details, add or remove a password, crop, page size, and a page editor; PDFs in, a new file for each out (`_rotated`, `_trimmed`, `_extract`, `_numbered`, `_properties`, `_protected`, `_unlocked`), written under a hidden temp name and moved into place. It borrows PDF Toolkit's range parser (`ParseRanges`/`ResolveRanges`), `UniquePath`, `SafeName`, `PlainError` and `DefaultFolder`.
  - **PdfSharp 6.2.4 facts:** `PdfDocument.PageCount` throws after `Save` (read it first). The library **decrypts while reading**, so `SecuritySettings.IsEncrypted` is false for every file it opened: ask the file instead (`HasEncryptEntry` looks for `/Encrypt n n R` in the first 16 KB and last 256 KB). Password trouble is reported only as words, classified in one place (`Classify`): "A password is required" (needs the open password), "The specified password is invalid", "To modify the document the owner password is required" (opens for reading, changing needs the owner password). A restrictions-only PDF gets a random owner password nobody keeps (the sidebar says restrictions can't be lifted then).

## Connections (learned on Connections)
- Reads Windows' TCP/UDP table (`Shared/Controllers/TcpUdpTable.cs`, the data behind `netstat -ano`) - no administrator rights, IPv4 and IPv6. It shows **who** is connected, never how much data moves (that needs ETW and admin).
- "Outside" = a remote address beyond this PC's own network: not loopback, private (10/8, 172.16/12, 192.168/16), link-local, carrier-grade NAT (100.64/10), multicast, or an IPv6 unique-local/link-local address. Listening ports and UDP sockets have no remote side, so they are never "outside".
- Count apps and connections with `ConnectionsManager.ActiveOutside` (drops TimeWait / Closed / LastAck), not with every row, or finished connections inflate the tiles.
- Read only while the page is showing: start the timer on `IsVisibleChanged` to visible, stop it when hidden (pages stay alive), and drop a reading that was still in flight (`_generation`).
- Rows have an identity (protocol, PID, both endpoints). A row whose state changed is replaced, not edited, so sorting and filtering stay correct; rows first seen after the first reading get a "New" chip until the next reading.
- Host names are a reverse DNS request per address, so they are **off by default**, limited (8 at a time, 2 s timeout), cached, and canceled when the page hides or the option is turned off. Never save addresses, app names, or host names in the settings file.
- PIDs are named with `Process.GetProcessById`; 0 and 4 are "System", and a process that ended or won't say is "Unknown". The cache is rebuilt from each reading so a reused PID is looked up again.
- Guided tour (6 steps, `Str_Tour_Connections_*`, in this order): summary tiles, search bar, the list, the Outside/Local/All toggle, "Look up host names", Export CSV. Tag new controls with `ctl:Tour.Key`/`Tour.Order` and add both `_Title` and `_Text` in en and es.

## Screen OCR engines and Settings › Text recognition (learned on adding Tesseract)

- Two engines behind one `RecognizeAsync`: Windows OCR (default) and the bundled Tesseract (`Engines\TESSERACT`, run as a process with `tsv` output — no NuGet wrapper). The engine and the Tesseract language are saved in Screen OCR's own `ocr_text_extractor.json` (`Engine`, `TesseractLanguage`), not in `settings.json`.
- Tesseract languages are `.traineddata` files downloaded from `tessdata_fast` into `AppPaths.TesseractData` (`DataRoot\Tesseract\tessdata`), never into `Engines\`. The first use copies the bundled `configs` and English there, because the `tsv` output needs `configs\tsv` in the same folder as the models. A download goes to `.tmp`, is moved into place, and is checked with `tesseract --list-langs`; cancel deletes the `.tmp`.
- Settings sections that grow their own cards live in a `UserControl` under `Shared/Views` with a `SettingChanged` event (`TextRecognitionSettingsPanel`, like `ClipboardSettingsPanel`) so `SettingsView.xaml` doesn't keep growing. Another page can open a section with `SettingsView.RequestedSection` + `ShortcutManager.OpenToolRequested`.
- Screen OCR reloads its settings every time the page is shown, because the engine and languages can change in Settings. Wrap the language-list refill in `_applying`: clearing a ComboBox fires `SelectionChanged` and would save an empty language.
- The language pill shows "engine · language", so it is always clear which engine produced the text.

## Screen Recorder segments (learned on adding screen switching and UAC skipping)

- A recording is one or more parts. Each part is its own FFmpeg process writing a fragmented MP4 into `<name> (parts)` next to the final file; stopping joins them (`ScreenRecorderManager.JoinAsync`). Same-size parts are joined with the concat demuxer and `-c copy`. Parts of different sizes (one screen vs. all screens) are fitted into the largest size with black bars and re-encoded. A failed join keeps the parts folder and names it in the message, so nothing is lost.
- Pause, resume, screen switch, and stop all go through one `SemaphoreSlim` (`_gate`) so they can't overlap. `_partEnding` stops `OnExited` from treating a deliberate stop as FFmpeg dying.
- Windows security prompts (UAC, lock screen, Ctrl+Alt+Del) run on the secure desktop, which no capture can see. `OpenInputDesktop` fails while it is up, even without admin rights, so a 150 ms poll (two matching reads in a row) detects it. That time is left out of the video and out of the timer.
- The recording bar's screen button appears only for the whole-screen target with two or more monitors. A switch costs about a second of video (FFmpeg stops and starts), and the hint says so.

## Video Compressor & Trimmer, and Speech to Text (learned on the first build of each)

- Both copy `Video to Audio`: files-only Input card (a dropped folder is expanded to the matching files; the card's `ItemsSource` is the row collection itself), a run bar whose button turns into Cancel, a results grid, and the shared Output card. Output is never overwritten (`OutputFolderManager.UniquePath` through the Output card's `ResultPathFor`), and work goes to a hidden `.name.compressing-<guid>.tmp` first.
- Video Compressor runs one video at a time (encoding already uses the whole CPU). Target size is two-pass `libx264`: video kbps = target bits / seconds - audio kbps, with a 100 kbps floor and a plain message when the size can't be reached. Quality mode tries the graphics-card encoders first (`VideoReplayManager.EncoderOrderAsync`, minus `h264_mf`) and falls back to the processor when one fails. `-progress pipe:1 -nostats` must be in the arguments or `ConverterManager.RunFfmpegAsync` never sees progress. Trim-only copies the streams, so cuts land on keyframes and the result can start a second or two early; the UI says so.
- When testing FFmpeg from a console project, read stdout and stderr at the same time: reading one to the end first deadlocks once the other pipe fills.
- Speech to Text converts to 16 kHz mono WAV with FFmpeg, then runs `whisper-cli.exe` (`Engines\WHISPER`, the CPU build, which needs the Visual C++ runtime) with `-oj` and reads the JSON offsets; `-pp` progress goes to stderr. Models are downloaded on demand into `AppPaths.WhisperModels` with the same temp-file-then-move pattern as the Tesseract languages, and a file under 70% of the expected size is rejected. The `.txt`, `.srt`, and `.vtt` of one file share a name: if any is taken, all move to "name (2)".
- Trimming is a large dialog (`VideoCompressorTrimWindow`, about 85% of the screen work area, clamped to 760 x 560 .. 1280 x 820, resizable), not an inline card: an inline card left the picture and timeline too small at laptop resolutions. The body is `VideoCompressorTrimEditor` (picture stage on top that grows with the window, then the timeline, then the times and the Reset / Save frame buttons). It applies every change to the item at once and the window restores the values it had on open when you press Cancel, Esc, or close it; Done keeps them. The Keep button is off while a run is going and for rows that are done. The picture stage stays black in both themes, the documented exception to "theme tokens only".
- Speech to Text: any Whisper language can be chosen (about 100). English-only models cannot do another language or Translate, so choosing one switches to the installed multilingual model of the same size (or any installed one) and says so; a run applies the same rule, so old saved settings cannot produce an English-only run in Spanish. Translate only goes into English.

## Big batches: memory by budget, not by file count (learned on the large-batch pass, 2026-11-06)
- Parallelism limits HOW MANY pictures are open, not how BIG they are. Any tool that decodes a picture in bulk opens it with `ImageLoad.Open(path, token, maxSide)` (`Modules/ImageLoad.cs`): header first, then it asks `MemoryBudget` (`Modules/MemoryBudget.cs`, about a quarter of RAM, 256 MB - 2 GB, strict order, a request bigger than the whole budget runs alone) for the bytes and gives them back on `Dispose`. Never call the GC to "free" memory.
- JPEG is decoded already reduced when `maxSide` is given (`MagickReadSettings.Width/Height` do NOT shrink a real photo). `ImageLoad.ConfigureLimits()` (App startup) makes ImageMagick spill to disk past the budget.
- Lists that can reach 10,000+ items: bulk collection, virtualized list, no per-row picture past a cap (Barcode/QR batch keep a preview for the first 5,000 rows), caches evict the oldest entries, never "clear all".
- Find Similar remembers fingerprints (`similar_cache.bin`, path + size + modified time + method) so a rescan only reads new or changed files.
- Theme tokens for pictures and stages: `MediaStageBg/Text/TextMuted` (fixed dark in both themes), `ScrimBg`, `SliderTrack`, `SelectionFill`, `HoverOverlayFill/Stroke`, `CheckerLight/Dark`.
